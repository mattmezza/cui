## Coverage and clipping, precisely

For options sx,sy and origins ox,oy, let q=max(1,sx,sy). Compute px=float(frac(double(q)*ox/sx)), py analogously, using `v-floor(v)` in double, then store float once. If float rounding yields1, retain that equivalent integer grid translation in both profile preparation and footprint mapping. Prepare the actual copied DROP/INSET profile with (q,px,py), retaining all existing geometry/float order and source empty-hole/kernel semantics. Validate before skipping even an alpha-zero or clipped shadow.

Target pixel (i,j) has **complete source footprint**
`[q*(i-ox)/sx+px, q*(i+1-ox)/sx+px) × [q*(j-oy)/sy+py, q*(j+1-oy)/sy+py)`.
Compute its near edge in double and add the constant dx=q/sx,dy=q/sy for the far edge, with the same operation order in planning/preparation. Denominator is always dx*dy, finite and positive. For every intersecting integer source cell [u,u+1)×[v,v+1), evaluate the prepared original kernel at float(u+.5),float(v+.5), quantize `lroundf(255*coverage)`, multiply by exact double rectangular overlap area, and sum in fixed Y-major/X-major order. Outside integer source support contributes zero; do not crop/renormalize the denominator. Final alpha is `lroundf(float(weighted_mean)*(layer.color.a/255.f))`, preserving the existing second byte rounding. Straight RGB is the layer's original byte RGB.

Core already multiplies ancestor opacity into the shadow layer alpha (`cui.c` shadow emission); do not apply ancestor opacity again. Do not reapply caster radii, element masks, SDF coverage or clip opacity: the source kernel already contains the required DROP/INSET shape. No additional target radius mask, resampling, down-q, four-tap fallback or hidden image remask is allowed.

Use integer source potential support from the extracted helper, without full-raster admission. Invert its edges to target-device doubles: `(support_edge-phase)*axis_scale/q+origin`. Outward floor/ceil yields the only candidate physical rectangle; intersect with viewport before integer conversion. An empty support/rectangle produces canonical zero x/y/w/h/bytes/taps and no plane. After successful domain validation, alpha-zero layers likewise produce empty work.

Apply the current painter's **hard logical center clip**, not area clipping: include a pixel only when its inverse logical center lies in the exact accumulated double clip. To prebound indices, device-axis clip center range is `[ceil(clip_near*scale+origin-.5), ceil(clip_far*scale+origin-.5))`; clamp doubles to viewport before integer casts and retain the existing exact inverse-center test as final authority. For a clip-rejected cell store0 and omit all source reads; never blend it. A clip does not shrink a retained pixel's source footprint or denominator. Portal/drop/fill/inset/underlay ordering comes solely from the Core-produced command sequence; no grouping or sorting by kind is permitted.

Every retained candidate rectangle cell with positive source-support overlap blends its prepared byte once, including alpha0 (the V1 straight-byte blend may canonicalize hidden destination RGB). Truly outside-support or clip-rejected cells never blend. The physical source-support cover maps a contiguous rectangle, so boundary occupancy can be recomputed from the same affine/support predicates without a second alpha/coverage application or occupancy plane. Distinguish these cases in transparent-target tests.

## Transaction quotas and admission

Proposed private engineering cap: **1,048,576 total intersecting source-cell taps across the entire transaction**, not per shadow, plus at most1,048,576 shadow output rectangle cells. No new public options field. A rectangle cell omitted by the hard clip costs zero taps; zero-valued source samples still cost taps. Duplicate cell evaluations across neighboring pixels/commands each count; there is no uncounted cache. Charge shadow rectangle cells plus background cells jointly against `options.max_pixels`; `max_pixels_per_background` continues to apply only to backgrounds. The tap/output caps are explicit rejection limits, not quality/optimality claims.

Preflight walks the complete list without allocation/provider/kernel calls, maintaining the existing exact double clip stack. Each shadow is domain-prepared by value and its candidate cells inspected. Intersect raw footprint floor/ceil with integer support, check finite endpoints/denominator, checked coordinate conversions and products, then add nx*ny to remaining transaction taps using subtraction/division before multiplication. A cap failure occurs before any kernel evaluation, allocation, scratch clear or target mutation. Validate actual intersected first/last half-centers and adjacency before conversion to float; never hide collapse by cropping or lowering q. Approved geometry/q/phase bounds keep active support below2^22; preserve explicit checks and extreme-sign tests. Empty inner ranges must short-circuit before any Y loop.

Bound preflight work separately: at most16384 commands, clip depth64 and1,048,576 visited shadow rectangle cells (the aggregate cell quota is checked before visiting a rectangle). Work per visited cell is O(1); rendering performs at most the admitted tap count, each using the unchanged bounded four-Y kernel or sigma-zero SDF. There is no full-source raster, unbounded scan, font callback or shadow cache.

Let N=list count, S=number of shadow commands (including validated empties), C=N*sizeof(cui_draw_command_v2), D=N*sizeof(existing paint descriptor), H=S*sizeof(new shadow descriptor), T=4*viewport_width*viewport_height, B=sum prepared packed background RGBA bytes, A=sum shadow rectangle A8 bytes. Exact counted requests are:

- CPU block: C + T + B + A, in that allocation order (all regions after C have byte alignment, so no added CPU padding).
- Metadata block: D + pad(D,alignof(shadow descriptor)) + H, with checked padding only when S>0. The first region begins at the allocator's already-required fundamental alignment; static-assert both descriptor alignments fit it.

Require CPU<=options.cpu_bytes<=32MiB and metadata<=options.metadata_bytes<=1MiB; all products/sums use checked size_t arithmetic. Existing background texture/transfer checks continue for B. Software shadow A8 planes are CPU-only transaction memory, never uploaded; do not pretend they are future GPU texture accounting. Keep the adapter-owned bytes separate from caller target/input memory and eventual class1/class3 font/dependency state. No font state is used by this slice. Stack scratch remains bounded by the existing64-entry clip arrays plus one current profile/plan/loop state, with no per-cell stack array. Existing target/input resources remain borrowed and stable through return, including allocator callbacks.

No old/current frame transaction memory is retained after return. Peak live adapter-owned heap is exactly the two requested blocks above; allocation headers/allocator internals belong to the existing allocator contract. Include the already-existing target allocation separately when an eventual initialized renderer owns it; do not charge the borrowed target to this private workspace or call this a total-process bound.

## Preparation, painting and recovery

After complete admission, set target busy before the first allocator callback, acquire the two blocks with the existing workspace, copy commands, populate descriptors and prepare all backgrounds/shadow A8 planes. Repeat checked plan construction from copied commands; immutable-input contract applies across allocation callbacks. Every `workspace_take` must be checked explicitly before dereference. Reject unexpected nonfinite/out-of-range kernel coverage or plan disagreement as INVALID_ACTION before any scratch clear. No allocation occurs inside profile evaluation/painting.

Only after every resource plane succeeds clear scratch and paint original command order, using the existing straight-RGBA byte source-over and exact clip. Shadow paint reads one A8 value and original RGB; it does not invoke the kernel or allocate. Then publish target rows with original stride, leaving target row padding untouched. All failure paths free both blocks, clear busy and leave every target/padding byte unchanged; allocator/provider callback side effects are not rollback claims. An invalid late command, either allocation failure, bad resource alias, capacity failure or reentrant attempt must preserve the target and allow a valid retry on the same target. TEXT still rejects before allocation, including TEXT after otherwise valid shadows; no incomplete successful frame/public support query is allowed.
