# Root

`cui_root` is a caller-owned, per-window content and overlay host. Base owns the root and its ordered plugin registry. Applications register plugins during initialization, then create one root and a separate plugin-instance array for each window. Registration uses an application-defined numeric key: registering the key again replaces its factory in place for future roots, while existing roots keep their snapshot and state. Factories receive a per-window pointer and return caller-owned state that must outlive the root.

Each frame runs plugin `prepare` callbacks in registration order, then `style` callbacks, then applies an optional instance style refinement. Set the corresponding flag for each override field so unspecified plugin defaults remain intact. `decorate_begin` callbacks wrap the root in reverse registration order and matching `decorate_end` callbacks close the wrappers in registration order: the last plugin is outermost. Application content renders once; plugin overlays render once in registration order above it. All callbacks run synchronously. Root requires a viewport starting at `(0, 0)` with positive finite dimensions. The plugin registry and root arrays have caller-specified capacities; invalid root capacity is rejected before any factory executes. If a later factory fails, Root calls each earlier plugin's optional `destroy` hook in reverse order and leaves the root uninitialized. `cui_root_dispose` calls those hooks for a completed root; factories that allocate resources must provide a matching hook.

For a styled window, initialize and bind caller-owned Dialog slots and an initialized Notification state once with `cui_root_bind_facilities`. Pass a `cui_surface_state` initialized as a Dialog or Alert to `cui_root_dialog_open`, or a Sheet to `cui_root_sheet_open`; both accept a content callback. `cui_root_render` mounts the active Sheet, Dialog stack and Notifications after application content on every frame. The app content callback never needs to mount those layers. Dialogs keep their own focus scopes and Escape handling; nested dialogs paint above their parents. At most eight dialogs can be bound so all Dialog layers remain below the Notification layer. Closed Dialog slots are reclaimed on the next open. The root does not own the surfaces, notification entries, plugin state, strings or callbacks.

For Base-only composition, call `cui_base_root_render` with application content and optional facility callback. It has no dependency on a styled plugin. A host can install `cui_root_set_copy_hook` to copy its current selection on an unconsumed Ctrl/Cmd-C event. The callback retrieves selected text and writes to the host clipboard; Root does not infer selection from widgets. Input and Textarea consume their own copy events before this fallback runs.

This covers the source Root's per-window state, registry snapshots, render stages, instance style precedence and automatic Sheet/Dialog/Notification mounting. The source's entity observation, deferred notifications, OS window helper, platform window chrome, global text-selection scope, tooltip/native-menu/touch-selection hosts, and copy selection layer are outside this portable C API. Applications drive frame scheduling and window lifecycle explicitly; the root makes no claim of complete upstream parity.
