# Bridge scalar, text and selection notification checkpoint

Status: **C opt-in poll, four-producer SCALAR and four-producer plain TEXT slices implemented in this branch**; see [the scalar guide](../BRIDGE_VALUE_NOTIFICATIONS.md). Selection and all value-poll wrappers remain proposals. Original read-only audit: `7bb03cd8`; the implementation preserves ABI/layout, generated SDKs and timing. This extends [the shipped V1 guide](../BRIDGE_NOTIFICATIONS.md) and [original bridge checkpoint](BRIDGE_TYPED_EVENTS_SLICE.md). All new names below require review. Preserve the 78-family manifest and queued notification boundary; this is not foreign synchronous veto, a new queue or direct-C event-facade forwarding.

## Blocking compatibility decision: reserved is not automatically deployable

[The C header](../../include/cui/cui_bridge.h) freezes `cui_bridge_notification_v1`, its union, exact-size query and optional symbols. Tags SCALAR=2, TEXT=3 and SELECTION=4 already have space; TEXT uses the existing separate UTF-8 buffer, SCALAR the reserved double and SELECTION the reserved slot/generation handle. Existing flags only express frame presence. No struct, ABI-version, old event layout, existing flag or union size change is needed.

However, current [Go `PollNotificationV1`](../../bindings/go/cui/native.go) and [Rust `decode_notification_v1`](../../bindings/rust/src/lib.rs) reject reserved/unknown tags **after the C poll has consumed the record**. Python's [decoder](../../bindings/python/cui_bridge/__init__.py) and [JS view](../../bindings/node/index.cjs) instead fall back to Legacy; they do not expose those typed values. A capability bit alone cannot protect an old consumer calling the old poll. Do not start emitting reserved tags from `cui_bridge_poll_notification_v1` unconditionally.

Recommended additive opt-in, retaining the existing schema:

```c
/* Bit positions are payload tags, not node kinds. Only 2, 3, 4 accepted. */
#define CUI_BRIDGE_VALUE_SCALAR_V1    (1u << CUI_BRIDGE_PAYLOAD_SCALAR)
#define CUI_BRIDGE_VALUE_TEXT_V1      (1u << CUI_BRIDGE_PAYLOAD_TEXT)
#define CUI_BRIDGE_VALUE_SELECTION_V1 (1u << CUI_BRIDGE_PAYLOAD_SELECTION)
CUI_BRIDGE_API uint32_t cui_bridge_notification_value_payloads_v1(void);
CUI_BRIDGE_API cui_bridge_status cui_bridge_poll_value_notification_v1(
    cui_bridge_app *, uint32_t struct_size, uint32_t enabled_payloads,
    cui_bridge_notification_v1 *out, char *text, uint32_t capacity,
    uint32_t *required_capacity);
```

The query advertises implemented value categories; callers request only categories their decoder understands. Unsupported/reserved mask bits fail INVALID_ARGUMENT before queue cleanup/consumption, with outputs intact. Mask zero returns the existing initial-allowlist view. The old V1 poll permanently retains its initial typed allowlist: a newly captured value tag is returned there as LEGACY with the unchanged complete legacy fields/text. The new poll also downgrades unrequested value tags to LEGACY. This is selecting an already-captured view, not reconstructing a value at poll time. Existing CLICK/BOOLEAN/TABLE/SURFACE behavior is unchanged in both polls. Both drain the same queue as all legacy polls.

Keep `notification_versions()` bit0 and the size contract unchanged. Optional new symbols plus the category query negotiate value support; do not overload schema-version or frame flags. A new layout or richer security/selection metadata would need its own reviewed version. An alternative is V2 with all wrapper upgrades; simply changing old V1's default producer tags is incompatible with shipped Go/Rust decoders.

There are only legacy CLICK, CHANGE and CLOSE event names; wrappers' `on_change` is not direct C's typed CHANGE/COMMIT/SUBMIT contract.

| Producer / source seam | Actual stored snapshot and timing | Proposed treatment |
| --- | --- | --- |
| Slider / `bridge_render_node` | Component uses local float, writes node double, then one `bridge_change` for aggregate changed. | Initial SCALAR allowlist. Copy `node->value` directly, preserving the float-to-double result; not full double-precision slider interaction. |

| InputGroup / `bridge_render_input_group` | Input changed enqueues parent text; addon activations independently enqueue CLICK on the child. | Initial plain TEXT allowlist; retain input-before-addon enqueue order and unchanged addon click view. |
| RadioGroup, Tabs, Select / `bridge_render_group` | Existing legacy aggregate returns; final Core item ID mapped back to a direct child slot in `node->value`, then one enqueue. | Initial SELECTION allowlist. Capture the validated full selected handle at enqueue, not a Core ID or reconstructed current selection. |
| List / same | One aggregate activation can occur even when selected ID repeats. Final mapped slot survives. | Initial SELECTION snapshot only; explicitly retain the existing CHANGE event name and repeat notifications, not per-command/per-transition claims. |
| Stepper / same | Current step mapped to direct child slot after aggregate change. | Initial SELECTION allowlist, with step identity distinct from numeric page/index. |
| Combobox / same | Query aggregate enqueues before selected-slot mapping; selection aggregate may enqueue again after mapping. Both records currently contain query text and a selected handle. | Defer: a node-kind-only tag switch cannot truthfully distinguish query versus selection reasons. A later private reason discriminator at these exact enqueue calls can classify without changing order/count; no JSON parsing or query inference from selection changes. |
| Menu and DropdownButton / same | Aggregate menu command maps last leaf to child slot; Dropdown primary action separately enqueues CLICK. | Remain LEGACY CHANGE. | Tree, Carousel, Command, Sidebar, Dock, Settings | Specialized reducers and/or callbacks use differing child/index/reason models; `bridge_change` opportunistically captures a direct child handle. | Remain LEGACY pending individual producer audits. | TextView | Selection anchor/cursor changes enqueue selected text, not edit-model change. | Remain LEGACY; TEXT-change naming would conceal a different event meaning. |
| OTP, Speech | OTP `.changed` copies value; speech provider callback copies transcript plus status/event type. | Remain LEGACY pending security/event-specific review; no new sensitive-text promise. |

Selection capture already validates slot <= max_nodes, live generation and direct parent equality in `bridge_change`. The bridge limit is1024 nodes; slot and generation remain **uint32**, never a Core uint64 `cui_id`. Selection has no previous item, reason, input index or copied activation. The initial allowlist must treat node value0 as explicit empty handle `{0,0}`; a nonzero value that fails the existing child validation stays LEGACY rather than being mislabeled an intentional clear. Do not resolve historical selected handles to a replacement slot generation.

`bridge_change` copies `checked`, double `value`, optional selected handle and text before advancing queue count. Typed capture must occur alongside that same snapshot and preserve allocation-failure and queue-full behavior. No observer adoption, callback retiming, per-event replay, getter reconstruction or sorting by input index belongs in this slice.

## Numeric, text and security boundaries

[Numeric setters](../../src/bridge/cui_bridge.c) reject nonfinite values. `set_range` restricts Slider bounds/step to float-compatible magnitude (±16777216); NumberInput retains double storage. Capture the **actual committed value**, including its precision, without decimal JSON round trips, integer truncation or JS BigInt conversion. All language scalar views use IEEE binary64 (`float`, `number`, `float64`, `f64` respectively). Exact uint64 frame sequence remains Python int / JS bigint / Go uint64 / Rust u64, independently of scalar values. Do not use scalar double to transport arbitrary integer IDs.

Current bridge Input options expose disabled state, not password/masked/content-purpose configuration; searching the canonical bridge header/implementation finds no secure-text option. `bridge_change` unconditionally copies the underlying edit bytes. In contrast, [direct C Input events](../../include/cui/cui_text_input_events.h) redact text when masked/password purpose is set. The bridge does not consume that facade and does **not inherit its redaction**. Initial TEXT support is explicitly plain Input/Textarea/Editor/InputGroup only; no claim of secure input support. Future secure configuration must fail closed for notification text in legacy and typed views, including `legacy.text`; redacting only the typed field would still leak. Adding redacted-versus-empty metadata cannot silently repurpose V1 flags (existing Go/Rust validate them); review a versioned extension first. Do not implement password support by later getter checks that miss already-queued secret copies.

Plain edit buffers are4097 bytes including NUL, NumberInput128; OTP separately allocates4097. TextView has4097 source and8192 rendered capacity, speech has separate transcript storage. These are producer limits, not a universal V1 text cap. Preserve UTF-8 byte lengths, empty strings, owned snapshots and NUL-inclusive capacity arithmetic. Before enabling any additional producer, prove its length fits uint32 and `length+1` without overflow at enqueue and poll; never narrow unchecked `size_t`. Poll remains allocation-free, truncates nothing and parses no JSON.

Existing wrappers start at4097 and retry once up to1MiB including NUL. Preserve this explicit policy, error propagation and no live-record consumption on C CAPACITY; wrapper decode errors after successful C consumption are not retryable. Queue-full failure can follow applied mutation and leaves prior records; no rollback claim. Preceding stale origin cleanup can occur before CAPACITY, as today. Typed storage uses existing fixed per-slot union plus existing text allocation, not another queue or new per-event typed allocations. Result copies own no live nodes.

## Language surface and compatibility matrix

Keep existing manual polls and legacy dispatch unchanged, including their initial allowlist and current timing. Add explicit opt-in methods below, using the new optional C symbols, exact-size query and requested category mask. Do not auto-select them from `step`, `run` or `dispatch`.

| Consumer | Shipped current V1 / reserved-tag behavior | Proposed new owning manual API |
| --- | --- | --- |
| C | Initial allowlist; raw fixed union and caller text storage. | New value-poll symbol above; SCALAR=`payload.scalar_value`, TEXT=separate complete UTF-8 copy, SELECTION=`payload.selected`. All remain CHANGE. |
| Python | Frozen dataclasses; reserved/unknown tags fall back to Legacy. Optional symbols support older libraries. | `App.poll_value_notifications_v1() -> Iterator[ValueNotificationV1]`; union of existing classes plus frozen `ScalarChangeNotificationV1(value: float)`, `TextChangeNotificationV1(text: str)`, `SelectionChangeNotificationV1(selected_handle: tuple[int,int], selected_node: Node | None)`. |
| Node JS / TS | Frozen records; reserved/unknown fall back to legacy. Addon preserves exact bigint frames; canonical declarations in `bindings/typescript/index.d.ts`, Node `.d.cts` re-exports. | `App.poll_value_notification_v1(): ValueNotificationV1 | undefined`; new union extends existing `NotificationV1` with `scalar-change/value:number`, `text-change/text:string`, `selection-change/selectedHandle:NotificationHandleV1,selectedNode?:Node`. Keep existing union/API unchanged. Addon must read the typed union double/handle, not legacy getter state. |
| Go | Owning `NotificationV1`; reserved/unknown tags error after consumption. Dynamic optional-symbol path and bundled SDK builds both exist. | `App.PollValueNotificationV1() (ValueNotificationV1, bool, error)`; new type wraps existing notification or typed scalar/text/selection variant with float64/string/full Handle. Do not silently add incompatible cases to callers' established contract. |
| Rust | Owning enum; reserved/unknown tags produce protocol error after consumption. New enum variants could also break downstream exhaustive matches. | `App::poll_value_notification_v1(&mut self) -> Result<Option<ValueNotificationV1>>`; **new enum** `Existing(NotificationV1)`, `ScalarChange(MetadataV1,f64)`, `TextChange(MetadataV1,String)`, `SelectionChange(MetadataV1,RawHandle)`. Do not modify the exhaustive old enum for this slice. |

These are proposed signatures; compile-ready naming/type details should follow each wrapper's existing conventions during its review. Shared metadata and complete legacy snapshots remain available in every variant. Text ownership is independent of source removal/app destruction. Optional selected-node wrappers are conveniences resolved by exact slot+generation where supported, not owning nodes; retain the handle if stale. Rust can retain its raw-handle convention rather than invent a resolvable live node.

Older libraries: new optional symbols absent => explicit unavailable error without draining through an old API; legacy functions continue to work. Libraries with only part of the reviewed allowlist advertise category support accordingly; new wrappers request only compiled-known advertised bits. Unknown future mask bits are never automatically enabled. Unknown payload/kind combinations from a malformed provider are protocol errors; do not coerce them to a valid scalar/selection. Old methods on a newer library receive downgraded LEGACY value records and continue working. This compatibility policy needs real tests, not a version comment.

Canonical wrappers and [Go/Rust SDK generation](../../scripts/generate_go_sdk.py) must land in separately reviewable commits. Bundled C headers/sources/provenance and exports must match; dynamic wrappers must prove old-library availability separately. No hand edits to generated SDK copies. Current guide's statement that Go/Rust availability is independent is not evidence they are missing: [Go implementation/tests](../../bindings/go/cui/notifications_v1_test.go) and [Rust implementation/tests](../../bindings/rust/tests/notifications_v1.rs) already ship initial manual views. Update human/LLM documentation and generated skill/index resources through integrator-owned workflows after API review.

## Independently reviewable implementation and proof

1. **C opt-in plus SCALAR**: old-symbol downgrade, capability/mask validation, explicit four-kind producer allowlist. Own canonical bridge header/implementation/private payload only as needed, new value-notification fixture and guide. Existing V1 ABI bytes/size and legacy APIs remain fixed. Prove NumberInput double values beyond float precision, Slider/Rating exact promoted float, Pagination integer page; no events from setters/render-only progress. Invalid mask/size leaves queue/output untouched; old/new/legacy interleaving remains one FIFO.
2. **C plain TEXT**: explicit four-kind allowlist at existing enqueue points, no added submit events. Prove non-ASCII UTF-8, empty versus nonempty,4096-byte boundary, delayed copies versus subsequent edit, originating removal/app destruction, exact capacity/no partial outputs, queue-full and allocation failure without false rollback. Assert unchanged event counts for multiple edits within one frame. Document unsupported secure configuration; a synthetic secure-model future guard test is not evidence of a shipped secure bridge API.
3. **C SELECTION**: explicit RadioGroup/Tabs/Select/List/Stepper allowlist. Prove selected slot+generation, clear0, stale selected removal/reuse, final-state aggregation including a return to the initial value where legacy emits nothing, List same-item repeat, disabled/inert behavior. Menu/Dropdown, Combobox query+selection, Command and JSON producers remain LEGACY. Test invalid nonzero child identity stays LEGACY, without fabricating a clear.
4. **Owning wrapper updates**, Python, Node/TS and Go/Rust independently reviewed against those C capabilities. Real queue tests must cover all enabled categories, shared old/new drain, lifetime copies and selected-generation behavior. TS strict narrowing includes the new union while old union source fixtures remain valid; Rust compile fixture preserves old exhaustive matching. Regenerate SDKs only through integrator workflow after canonical source/exports are wired.
5. **Protocol/compatibility matrix**: reuse/extend the separately owned [test-only native provider](../../bindings/tests/notification_v1_fixture.c) in a reviewed test commit, not producer code. Deterministic records cover uint64 frames `2^53-1`, `2^53`, `2^53+1`, UINT64_MAX; full uint32 handle extremes; binary64 values not exactly representable in float; reserved/unknown tags/kinds; absent optional symbols; wrong native size; capability masks; empty/large text; capacity0/non-increasing/repeated/>1MiB responses. Distinguish these conversion/protocol records from real input and real enqueue tests. Old Rust/Go wrappers against new C must successfully consume newly classified producers through the old symbol as LEGACY.
