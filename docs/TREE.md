# Tree

`cui_tree.h` adds a retained bounded hierarchy, independent headless behavior and an ordinary styled Tree. Nodes are a preorder array of nonzero stable keys, borrowed labels, depths and disabled flags. The first depth is zero, depth increases by at most one and the maximum is 63. Application-owned expansion flags and selected key remain controlled. Nodes/labels must remain immutable and alive until a successful rebuild; changing expansion flags externally requires rebuilding the visible projection.

Create a model with capacity up to 100,000 nodes. Two preallocated banks hold hierarchy, visible projection and key lookup. Rebuild validates depth/keys and swaps banks only on success, preserving the preceding model on capacity, duplicate-key or invalid-input errors. There are no allocations after create. Node lookup uses a bounded open-addressed key table; parent and branch lookups are constant time. Rebuild and expansion changes flatten the hierarchy in linear time. The memory-byte accessor reports model-owned allocations. The array representation also lets an application replace asynchronously loaded data without a platform-specific filesystem dependency.

Rows select and report activated keys through ordinary pointer or Enter/Space activation. Separate expand buttons toggle branches. Up/Down moves between enabled visible rows, Home/End selects endpoints, Left collapses or moves to an enabled parent, and Right expands or visits an enabled direct child. Consecutive events reduce in input order. Selection follows navigation unless manual selection is requested. Disabled rows cannot activate/navigate; enabled descendants of an externally expanded disabled parent remain independent. Collapse preserves a hidden selected key until the application or a later selection changes it. ASCII typeahead supports accumulating prefixes, a 750 ms timeout, wrapping and repeated-letter cycling; Unicode case folding is pending.

Semantic snapshots identify TREE and TREEITEM roles, stable parent relationships, expanded/selected/disabled details and a roving Tab stop. Expand controls are pointer/programmatic focus targets with no additional Tab stops. Native accessibility bridges and set-size/position metadata remain pending.

Fixed-height virtualization computes the visible/overscan range arithmetically and emits only that window. Scroll state accepts fractional logical pixels. The styled renderer uses clipped child translation, preserving both the tree clip and its ancestor clips. Overscan rows above/below the viewport cannot receive pointer activation. Keyboard navigation scrolls the active cursor into view; wheel events update controlled scroll state. Separate reduce/submit APIs let custom renderers apply the final scroll offset before registering semantics inside their clipping ancestor. The combined base function emits no draw commands. Variable row heights, automatic tree scrollbar chrome and retained scroll anchoring across arbitrary external reorders remain pending.

The styled Tree paints indented theme-colored rows, textual expand/collapse affordances, selected surfaces and focus borders. Its base model and public node accessors support application-specific row painting. Icons, custom row callback convenience, context menus and drag/drop are not implemented; none are claimed by the parity manifest.

Tests cover transactional rejection and preserved models, parent/subtree structure, expand/collapse, a 10,000-node viewport and 1,000 deterministic expansion rebuilds compared with an independent ancestor scan. Routed keyboard/pointer tests run all four themes and verify multiple navigation events, disabled skipping, direct-child/parent behavior, expansion controls, typeahead/repeated letters, activation, manual selection and semantic hierarchy. Fractional-scroll tests verify measured row positions and reject overscan pointer targets. The same event suite builds with `CUI_TREE_BASE_ONLY`, links only core/base Tree and emits no draw commands. Strict C11 warnings, fully instrumented ASan/UBSan and existing CTest pass before submission. Build/distribution registration belongs to the integrator.

The root exposes scroll offsets and extents for core wheel routing. Wheel events
apply only when routed to this Tree; ancestor boundary bubbling is handled by
core. Scrolling does not repeatedly reveal the focused row; keyboard navigation
reveals it again. Tree-item semantics include the one-based hierarchy level.
