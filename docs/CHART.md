# Charts

`cui_chart_render` rasterizes into caller-owned, straight-alpha RGBA8 pixels. Allocate at least `width * height * 4` bytes and keep the buffer alive through renderer completion. Call it before `cui_chart` each frame. Both functions are allocation-free. Set `logical_width` and `logical_height` to render at a higher pixel density than the chart's logical size; hit coordinates use logical size. A nonzero `data_revision` enables a cache: increment it whenever a datum, series, or link changes in place. Zero disables caching. State, input arrays, strings, and output pixels remain caller-owned.

The adapter covers seven chart families. Line and area accept natural, linear, and step-after curves and up to seven additional series. Bars support top, bottom, left, and right alignment, including negative values. Pie supports donut radius and slice padding. Candlesticks validate OHLC and use bullish/bearish colors. Sankey computes an acyclic graph's longest-path layers and proportional node/link widths; `cui_chart_sankey_layout` exposes the caller-owned node geometry and rejects cycles before changing output. Radar accepts the same additional series, a pinned maximum/outer radius, translucent fill, and optional vertex dots around dimension spokes. The theme helper fills absent colors, and the styled adapter draws category/value labels, simple legends and hover values as CUI text over the bitmap. Numeric label and hover formatting callbacks write into bounded buffers. `cui_chart_hit_test` returns a point or slice, a radar dimension, or a Sankey node.

This remains partial against the pinned GPUI Kit source. It does not yet cover custom gradients, advanced bar labels/corners/spacing, custom radar element labels, Sankey relaxation and labels, reveal animation, or arbitrary tooltip content. Value-axis gutter size is fixed rather than measured from text. `cui_plot` remains available for independent scales, ticks, pan/zoom, and clipping.
