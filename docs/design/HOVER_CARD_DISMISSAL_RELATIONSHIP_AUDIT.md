## Smallest compatible dismissal slice proposed

Add an independent sibling submission descriptor/API rather than resizing `cui_hover_card_policy` or changing conservative outside_tap. A typed release policy chooses LEGACY/strict-tap/raw-primary-release; zero/NULL delegates exactly to the current extension. Raw release is meaningful only with explicit TAP_TOGGLE. It examines eligible unconsumed primary POINTER_UP outside previous valid panel bounds, without requiring matching down or a movement threshold; consumption/modal permission are explicit CUI routing rules, not a claim about undocumented upstream listener dispatch. Trigger accepted activation retains frozen entry-open precedence; disabled/global Escape and placement rejection retain current ordering. No event consumption, capture, modal ownership, dispatcher change or new retained resource is proposed. Invalid policy fails before mutation. Existing contact workspace is used only for strict taps.

Before implementation, freeze names and whether raw release excludes the trigger region: source mouse-up-out is relative to content alone; accepted trigger activation must win using entry-open, including an outside release in the same submission. Do not silently substitute the existing both-regions test. Snapshot previous grid/bounds once; evaluate queued releases in order, preserving one final legacy callback, not a new per-input event stream.

Tests: legacy/NULL/zero draw and semantic oracle; strict policy unchanged; raw inside-down/outside-up, unmatched release, above-threshold drag, outside-to-inside release, trigger release with accepted and rejected activation, secondary button, consumed release, cancellation/gesture characterization, missing/invalid bounds, modal denial, disabled, Escape, multiple queued releases and independent cards. Real pointer/key/AT trigger activation and exact final callback timing remain required. Native private wrapper + existing WASI extended suite; gallery opt-in and actual-WASM mouse/touch proof only after API review. No automatic mobile detection.

## Accessibility architecture decision required separately

Core `cui_semantic_details.expanded` is a bool (`include/cui/cui.h:310`): false cannot distinguish absent from explicit collapsed. AccessKit (`backends/accesskit/cui_accessibility.c:190-191`) emits expanded only when true or TREEITEM; controls is separately emitted when its target resolves (`:228-230`). Thus the existing Core snapshot relationship is implemented, but ordinary closed trigger cannot reliably announce explicit collapsed state through native AccessKit.

Do not fix this by setting expanded=false on every Button or by inventing a HoverCard role. A complete optional-state contract needs an explicitly reviewed Core presence representation and corresponding adapter/equality/serialization/bridge handling. Prefer a generic presence mask with an EXPANDED bit and bool value over a component-specific adapter exception; zero must preserve all old semantic behavior. This changes public semantic layout and requires matching-header/library rebuild and binding review. It is outside this component-only checkpoint. Required tests include absent/false/true, removal and omission, closed initial node, open-close, resource rejection, adapter tree updates and browser serialization; live screen-reader proof remains distinct from snapshot tests.
