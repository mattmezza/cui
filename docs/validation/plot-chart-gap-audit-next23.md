## Smallest complete next vertical slice: owner Plot motion projection

Proposed append-only API for integrator review: a portable `cui_plot_motion` value containing enter/exit/appear transition policies and pointer spring policy, with explicit Base and styled constructors. Append an optional projection to Theme with an explicit presence flag; zero/absent retains existing Chart defaults and generic PlotElement explicit policies. Provide a checked resolver/helper that copies owner policy into styled PlotElement options without storing borrowed Theme pointers. Chart gets an optional explicit policy presence flag/value appended to options; explicit policy wins over projected owner policy, which wins over legacy default. Preserve existing `appear_duration`/`hover_duration` as documented overrides; specify precedence before implementation. Explicit duration zero must mean instant when policy is present, unlike current legacy zero meaning default.

A complete slice must actually drive Chart enter, exit, appearance and pointer channels and PlotElement enter/exit/appearance; merely adding fields is insufficient. Pointer follow in generic Plot remains an explicit helper/callback responsibility unless a separate datum-position contract is agreed. Easing callback/user lifetimes remain borrowed through synchronous sampling; validate finite bounded durations/delays and spring inputs before state/UI mutation. Do not add platform types or force a global theme registry.

Required evidence: two simultaneous owners with different durations/curves and no state leakage; exact source default samples including quartic appearance; enter/exit reversal; first-entry pointer snap and subsequent travel; explicit instant override; reduced-motion completes every channel; no redraw after settling; invalid policy preserves outputs/state; Chart bitmap, dots and tooltip geometry visibly follow resolved policy. Browser mouse and real touch/long-press host path must exercise a real story, not an exported-state-only model probe. Existing default-motion tests are useful regressions but not proof of new projection.

## Current-frame integration: separate reviewed dependency

Do not claim `cui_bounds` or end-of-frame tracking is current-frame prepaint. A complete automatic fix needs a Core contract that resolves the chart's current layout and clipping/occlusion before datum selection and overlay paint, exposes live global pointer even without a move event, and preserves existing single-frame input routing. A retained previous-frame rectangle plus invalidation is only eventual correction.

A scoped interim API may append `cui_chart_interaction_frame` (finite current global bounds, live global pointer, explicit visibility/occlusion gate) through a new checked `cui_chart_ex`, preserving existing wrapper semantics. The host must supply geometry matching this frame's layout; validate extent and transform to chart logical coordinates consistently. This mirrors the existing honest PlotElement seam, not automatic integration. It requires tests for stationary pointer while plot translates/scrolls/resizes, pointer exits current bounds, covered modal, changed logical/bitmap scale, reveal gate and disappearance. Do not implement without root approving the exact geometry ownership/lifetime and clipping semantics. Automatic source parity remains blocked on the Core prepaint contract even if this interim helper ships.
