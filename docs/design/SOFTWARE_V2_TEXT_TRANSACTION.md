# Transactional software V2 text (review proposal)

Source-only checkpoint on integrated581ef339; no implementation or compilation. The private painter now supports ordinary nontext commands, backgrounds and AREA shadows, but rejects TEXT. This proposal completes private TEXT painting before any public software support/render entry; four other adapters and bindings remain required. It preserves V1/public font ABI and does not claim CSS-exact text or universal font-format support.

## Actual seams and limits

`src/text/cui_text_prepare_internal.h` already records owned A8 glyph coverage, integer source positions, selected ink, source density and resolved text paint. The owner in `cui_text_alloc_internal.h` counts every CUI allocation prefix/payload against separate CPU/metadata budgets, with sticky errors and input/work ceilings. `cui_text_prepare_line` shapes original logical-size/contextual ranges, uses selected family/weight/italic/monospace/fallback faces, preserves visual glyph/cluster order and copies callback rows before return. Cold V2 raster never inserts into the existing glyph cache. The public NULL-owner path remains separate.

The actual recorder and `text_layout_draw` reject source density>16. Public scaled APIs have the same limit. The existing approved `SOFTWARE_V2_GLYPH_POLICY.md` proposed q=min(16,max(1,sx,sy)), then true per-axis inverse-center bilinear mapping. That mapping covers64x targets with an explicitly upscaled16x source; calling a scalar<=16 API alone does not implement the target transform. This checkpoint recommends revising **only the private source-density bound** to q=max(1,sx,sy)<=64, retaining the approved bilinear/ink policy. This is a review decision, not an already-supported API.

Color terminology matters: existing `cui_color_glyph_fn` supplies a selected **cluster ink plus A8 coverage**, not an intrinsic RGBA glyph bitmap. `raster_glyph_owned` uses FT_LOAD_DEFAULT/FT_RENDER_MODE_NORMAL, not FT_LOAD_COLOR; records contain no pixel-format/BGRA channel contract. Support contextual span colors fully, but do not call that color-emoji/SVG/COLR rendering. For nonempty owned V2 glyphs explicitly admit FT_PIXEL_MODE_GRAY with256 gray levels before copying; reject other formats before publication. Zero-sized glyphs remain valid empty work. Add the guard only to owned V2 lookup/callback paths, including hot cache hits; V1 flags/output stay untouched. Native intrinsic-color glyphs require a separately reviewed owned RGBA record/FT loading policy if desired, not silent byte reinterpretation.

## Alternatives and recommendation

| Option | Consequence |
|---|---|
| Keep q capped16 and explicitly inverse-map both target axes | Smallest code delta, but64x target magnification is4x source reconstruction. Honest under the earlier quality proposal; not native64x source raster quality. |
| **Recommend private q=max(1,sx,sy), up to64** | Full per-axis transform with source resolution at least each target axis; extend two private density guards, preserve public<=16 and all old<=16 outputs. Larger opaque FT raster work is explicit and can fail existing bounds. |
| Use FT anisotropic transforms/per-axis glyph sizes | Can reduce source work but changes hinting/raster identity, bearings, cache keys and potentially layout/raster coupling. Requires a separate font-pipeline decision; no need to solve it first. |
| Flatten a logical text image then rescale it | Loses per-glyph blend/order, colored overlaps, gradient anchoring and bounded source ownership; reject. |

Extend `cui_text_prepare_line` to density<=64. In `text_layout_draw`, allow<=64 only when owner!=NULL; NULL-owner/public paths retain<=16. No-Bidi owned simple recording already has a separate scalar-raster path and needs the same private admission. Logical font_size remains<=4096, so font_size*q*64<=16777216 fits the existing minimum32-bit FT_F26Dot6/long arithmetic; explicitly check before casts. Existing source-position bounds (|px|,|py|<=1e7) times64 fit int32, and existing bitmap-bearing/extent checks still apply. This is not permission to enlarge per-glyph4096-side/4M-pixel or frame8M-source-coverage ceilings. FT may allocate before those output limits become known (class3 below).

## Proposed private entry and capability contract

```c
/* Internal only; implementation compiled in the existing CUI_HAS_TEXT build. */
bool cui_text_prepare_context_available_internal(void); /* actual CUI_TEXT_BIDI */
static inline cui_error cui_software_v2_paint_with_font(
    cui_software_v2_target *, const cui_draw_list_v2 *, cui_color clear,
    const cui_render_v2_options *, cui_font *borrowed_font,
    cui_software_v2_alloc_fn, cui_software_v2_free_fn, void *user);
```

Keep existing `cui_software_v2_paint` as a wrapper passing NULL font, preserving its nontext behavior, exact nontext two-block requests and preallocation TEXT rejection. Common implementation uses compile-time CUI_HAS_TEXT guards around recorder calls; no-text builds must link without cui_text/FT/HB. The with-font function in a no-text build rejects TEXT; it cannot manufacture support. No generic provider callback registry or new input/dispatch architecture is needed. Eventually the real initialized software adapter supplies its own font/allocator/busy guard; callers cannot fabricate a public support record from this private entry.

The actual public text capability currently has only LETTER_SPACING; do not invent a Bidi bit or equate a borrowed font pointer with contextual support. Add the private context query above returning its compiled Bidi state, and pass a separate `context_available` boolean to the private structural validator (private signature/call-site updates only). Reject non-NULL contextual paragraph pointers and color spans when unavailable **before dereferencing their borrowed bytes**, including empty context and poisoned inactive raw text. Font availability and letter-spacing capability remain separately checked. Preserve the no-Bidi raw path, its current unsupported tracking/context/span restrictions, and authoritative non-NULL paragraph selection; no public legacy fallback change.

## Coverage, ink and original order

Choose q once from validated target axes; shape original logical font size/paragraph/style and record at q. Do not fold target origin into shaping, change paragraph byte ranges, rerun shaping at separate axis sizes, round target origins or scale layout advances. For target center P=(i+.5,j+.5), compute L=((P.x-ox)/sx,(P.y-oy)/sy), source S=q*L. A recorded bitmap's source centers are (gx+u+.5,gy+v+.5). Let tx=S.x-gx-.5, ty=S.y-gy-.5; floor each, read the four neighbors, use zero outside the owned bitmap, and bilinearly interpolate in double. Quantize coverage once with lround (ties upward), checking finite/range before scratch painting. No edge clamping, target area filter, atlas/cache lookup or additional glyph radius/opacity mask.

The bilinear basis has potential support `[gx-.5,gx+w+.5) × [gy-.5,gy+h+.5)`, not merely the bitmap rectangle. Derive outward physical cover from those double edges and viewport; use conservative clip culling and the same exact inverse logical center predicate as other V2 commands. Before any integer cast, intersect in double with viewport. Preserve hard clip membership; a clip never changes filter weights. Validate all planned inverse-coordinate extrema/ranges before clear. Track occupancy independently of alpha: blend if at least one in-bounds source neighbor has **positive weight**, even if its byte is0; skip when all such weights are absent. This preserves V1 hidden-RGB behavior at exact unit alignment without painting artificial zero-weight halo cells.

For target isotropic=q and integer source-to-target translation, a direct source-byte branch is permitted only after an exact alignment test; it must produce the same mathematical four-read result. Unit origin0 uses original source bytes verbatim. Blend glyphs in recorder callback order within each original TEXT command, and TEXT commands in list order among every other kind. Never max-merge glyphs or flatten all text into a single alpha plane; marks/overlapping colored glyphs need separate source-over operations.

For solid text use recorded `g->color` (ordinary command ink or selected cluster-span ink), **not** text_paint.color: existing V1 glyph() uses ink on the SOLID path. For LINEAR text paint sample existing `cui_text_paint_sample` at L, retaining its resolved logical anchor/endpoints, stop order/duplicate-position/premultiplied-channel/alpha rounding. Gradient+span colors remain mutually exclusive. Apply final alpha exactly as V1: `(unsigned)ink.a*coverage_byte/255` truncation once, then the existing straight-RGBA integer source-over. Command/span/stop alphas are authoritative; add no ancestor opacity multiplication. Source/paint stops remain borrowed and stable through synchronous return/session teardown; glyph A8 rows and descriptors are owned copies. No whole-list deep-snapshot claim.

## Exact allocation and work ownership

Keep the existing three classes: (1) borrowed pre-existing font graph/caches/runtime; (2) counted adapter/CUI transaction payload and prefixes; (3) new opaque FT/HB/SB/provider allocations/work. Only class2 fits the CPU<=32MiB/metadata<=1MiB envelope. There is no total-process/opaque-dependency byte or arbitrary-font time guarantee. Existing cache entries may be read; no new CUI cache insertion escapes the owner. Font graph mutation/concurrent close/render and allocator callback writes to inputs are forbidden through return; provider/runtime state changes on failure are not rolled back.

Base workspace CPU B0 remains copied commands + scratch RGBA + prepared backgrounds + shadow A8. Base metadata M0 is existing per-command/shadow descriptors plus an aligned per-TEXT array of `{first,last}` glyph-record pointers (count known before allocation); check every size/product/padding/take. A single transaction text owner uses limits CPU=options.cpu_bytes-B0 and metadata=options.metadata_bytes-M0, with the same distinct/aligned allocation/free callbacks and target busy guard. CUI layout/Bidi arrays, coverage copies and allocation prefixes charge owner CPU; record descriptors/prefixes charge owner metadata. Exact peak is B0+owner.cpu_peak and M0+owner.metadata_peak. Text introduces additional explicitly counted blocks; do **not** retain the nontext-only “exactly two blocks” claim for text-enabled frames. No text owner allocation before base quotas and validated input/work admission.

One recorder session appends all TEXT commands to a shared ordered glyph chain. Each per-TEXT range remembers first/last after successful recording, including an empty range. Keep records through complete frame preparation/painting, then teardown once. No per-glyph target plane or renderer-specific fields in the font record are needed: allocation-free planning computes each target rectangle, charges work, and painting recomputes the same pure geometry from immutable records/options. Each command's existing double clip descriptor remains authoritative.

Retain recorder limits:64KiB full paragraph,256KiB aggregate repeated input,64 faces,8192 attempts,4096 segments,65536 glyphs,8M copied source pixels,4M pixels and4096/side per glyph. Proposed renderer admission additionally charges **target glyph rectangle cells**, including clip-culling padding, jointly with background/shadow prepared cells against options.max_pixels<=8M. Check the entire rectangle addition before visiting it; each sample uses at most4 owned coverage reads and<=8-stop ink evaluation. This is separate from copied-source pixel count and dependency work. These are explicit engineering rejection limits, not quality or opaque allocator guarantees.

## Transaction and failure behavior

Validate list/options/aliases, host text availability/context/tracking/paint, input/work limits and all nontext plans before callbacks. Font size<=4096 must be enforced structurally, correcting the current validator's looser65535 check before dependency work. Explicit V2 line-origin admission is |bounds.x|,|bounds.y|<=1e6 (matching contextual draw); bounds.w/h remain inactive. Reject larger/nonfinite origins before font work rather than relying on a later recorder callback. This is a stated V2 text limit, not a change to arbitrary finite shape bounds or V1. Set target busy before base allocator/recording calls. Prepare all backgrounds/shadows and record all text; owner/session errors are sticky. After recording, preflight every glyph range, bitmap extent, coverage pointer, transformed support, sample-coordinate/cast range and aggregate output-cell quota. This may reject after dependency work/allocation, but always before scratch clear/target writes. No promise that output-dependent glyph sizes/work can be known before FT/HB runs.

Only after all resources and glyph plans succeed clear scratch and execute original command/glyph order with pure bounded sampling/blending. No font/dependency/provider call, allocation or validation failure may occur during painting. Release records/session before base blocks, preserve busy through every release callback, then clear it on all exits. Failed preparation/owner quota/opaque dependency/no-Bidi unsupported/malformed late command leaves every target/padding byte unchanged and permits a fresh-owner valid retry. Preserve allocation prefixes until their matching counted free; no arena impersonation, global allocator swap, font cloning or dependency replacement.

Then wire the complete private with-font painter (all current text command forms and full axis domain), using synthetic recorded-glyph sampling plus actual fonts. Do not publish a successful unit-only or raw-Latin-only partial renderer. The following public software entry is a separate final slice after this text path passes; other adapters remain outstanding.

Sweep counted allocations and dependency failure seams, first/late command failure, no-Bidi poisoned raw/context cases, owner/source/target aliases, pixel-mode rejection, source/output/work/budget exact/below limits, reentrancy/teardown/retry and cold-cache no-insertion.
