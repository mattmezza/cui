# Single-line Input pointer selection

The stateful Base Input reducer and styled `cui_input_ex` now consume host click counts for ordinary single-line text. Count zero/one preserves caret placement and Shift extension. A double click selects the source-defined word/whitespace range; a triple click (or higher count) selects the whole single line. Shift does not override double/triple selection. Masked double/triple click retains whole-value selection, avoiding disclosure of plaintext word boundaries.

This follows gpui-component 0.7.1 commit `87d10ae5e1299d1be18670a37570c5402f952e34`: `crates/base/src/text_boundary.rs:1–47`, `input/base/selection.rs:25–91`, and `input/base/state.rs:2297–2415,3190–3240`. The word classifier is deliberately distinct from Unicode word-navigation primitives: ASCII letters/digits/underscore, Latin U+00C0–024F and U+1E00–1EFF, Cyrillic U+0400–04FF and combining U+0300–036F connect; Unicode whitespace connects separately; punctuation, CJK and other scalars select individually. At most128 previous and128 following scalars connect. A400-character run clicked at byte200 therefore selects bytes72–329. End-of-value double click has no word and leaves selection unchanged. UTF-8 byte endpoints remain scalar boundaries; this is not an arbitrary grapheme/Unicode word-classification claim.

A double-click drag keeps its original selected word covered while extending the moving endpoint. Crossing left reverses the anchor; returning inside the original range retains the word; extending right uses the original start. It does not snap the moving endpoint to the whole destination word. The source clears sticky word state on triple-click: subsequent drag moves the line selection's end and may shrink it. This implementation preserves that behavior rather than inventing persistent whole-line drag.

Readonly controls permit selection; disabled controls suppress it. Consumed presses (including inline-token actions) do not reposition the caret or start word selection. Existing token-safe atomic selection expands token-interior endpoints. Consumed primary release still clears drag state. Keyboard/text events, cancel, blur, disable, model rebind and document revision invalidate the sticky range. No document mutation, validator/presentation call, hidden allocation or extra history edit occurs; normal selection breaks typing coalescing through the existing edit API.

Keep one zero-initialized `cui_input_behavior_state` per stable ID/model session, or one styled `cui_input_state`. Appended internal fields retain only offsets, numeric revision and an active flag; they never borrow text or retain the model pointer. Keep the model alive during reduction; reset caller state when destroying/recreating a model at a reused address, as with existing model identity contracts. The stateless legacy Base wrapper cannot retain a word-drag range between calls; use the stateful ex/reducer API for this interaction. Existing multiline reducers are unchanged: new word/line branches explicitly require a single-line model. Host adapters must provide actual click counts; zero remains an ordinary click.
