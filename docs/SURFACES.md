# Dialog, AlertDialog, Sheet and composed Popover surfaces

`cui_surface.h` adds application-owned surface state, drawing-free reducers and paired styled composition. A surface ID and its derived close, confirm, cancel and title IDs must be unique within the UI. Applications call `cui_surface_open` with a valid trigger, submit open surfaces every frame, and consume explicit outcomes with `cui_surface_take_result`. Call `cui_surface_close` during an active frame; if begin succeeded, its matching end remains required even after closing from a child action.

Dialogs, alerts and sheets trap focus. Popovers are nonmodal by default, with an explicit modal option. Escape and outside primary pointer presses can dismiss an open surface; the options disable either policy independently. Alerts suppress outside dismissal and their header close button by default. A decision callback can reject confirm, cancel or close before state changes. Closing withdraws current scoped semantics and restores an enabled trigger, including when a nested dialog closes back into its parent.

The styled begin/end accepts arbitrary CUI children. It draws a backdrop, title, optional description, close button and clipped body as viewport portals. `cui_alert_dialog` composes destructive confirm and outline cancel buttons. Each alert has an alertdialog semantic role; other surfaces use dialog, with a copied description and stable title relationship. A caller can compose its own alert actions using the documented derived IDs. Results persist until consumed or the surface is opened again.

Dialog dimensions clamp within an explicit viewport and optional uniform margin. Sheets support left, right, top and bottom placement with explicit width/height. Popovers use the existing side-based flip/clamp popup geometry. Nested surfaces require distinct IDs and explicitly increasing layers (default 100); the root does not yet provide an automatic overlay stack.

`test_surface` exercises actual styled confirmation buttons, rejected acceptance, pointer cancellation, all four themes, all four sheet edges, header close, Escape, outside dismissal, nested focus isolation/restoration and portal escape from an ancestor clip. The same behavior fixtures also run as `surface_base_only`, linking only core, models, overlay and surface base sources. Those fixtures emit only their own clipping commands, demonstrating no theme or component dependency in surface behavior.

This is partial GPUI Kit 0.7.1 parity. Remaining upstream scope includes automatic Root overlay management, frame-independent close requests, separate title/header/footer slots and styling options, viewport-limited independently scrolling bodies with pinned footers, configurable backdrop appearance, default viewport margins and top offsets, animated transitions, resizable sheets, and the complete Popover anchor/offset/arrow positioning contract. Existing popover flip behavior differs from upstream's anchored clamp-only default. Native platform accessibility and IME behavior remain separate unfinished requirements.
