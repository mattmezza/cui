# SDL3 compatibility adapter

This optional C11 adapter owns an SDL window and an `SDL_Renderer`. It is separate
from the SDL_GPU adapter. `cui_sdl3_driver()` reports the renderer selected by SDL;
the accelerated capability is set only for a selected driver other than
`software`. A detected OpenGL driver does not prove hardware execution rather
than a Mesa software driver.

Call creation, input polling, rendering and destruction on the main thread.
The caller owns the `cui_font` and must keep it alive until adapter destruction.
Primary, secondary and middle mouse buttons, stable touch contacts, keyboard
modifiers, repeated keys, precise wheel input, UTF-8 text and composition events
are translated. Compatibility mouse events generated by touch are suppressed. Window resize/expose invalidates the UI. Quit and
window close cause `cui_sdl3_poll()` to return false.

The clipboard-only `cui_platform` interface supplies `clipboard_set` and
`clipboard_get`; its `poll` and `text_input` callbacks are null. The getter's
storage lasts until the next getter call or adapter destruction. Embedded NUL
bytes are rejected on set. SDL text input is enabled at creation. The adapter forwards composition/preedit
with UTF-8 byte ranges and scopes commits to the original focused control. The
focused painted caret updates the host candidate rectangle. See [IME](../../docs/IME.md)
for the four tested consumers and remaining physical-device/OS validation.

Rendering supports solid fills, rounded rectangles and borders, nested rectangle
clipping, source-alpha blending and HarfBuzz/FreeType glyph coverage. Rounded
geometry uses one horizontal strip per pixel row; it has no multisample edge
antialiasing. Textures persist in an LRU cache with at most 256 entries and 4 MiB
of stored grayscale coverage (up to 16 MiB of RGBA texture data). A cache key uses
dimensions, coverage hash and byte comparison; texture color/alpha modulation
allows reuse across theme changes. Allocation, font and draw failures propagate
as `false`. Glyphs that exceed the cache memory budget fail explicitly.

Analytic triangle meshes use bounded CPU coverage rasters uploaded as ordered
SDL textures. Per frame the adapter permits 256 triangles and 8 million clipped
texels (32 MiB uploaded RGBA), plus one triangle scratch buffer of up to 32 MiB;
SDL/driver allocations are additional. Unsupported transforms, malformed commands
and capacity exhaustion fail explicitly. Mesh preparation occurs before clearing;
later draw failures are not whole-frame atomic. Resources are released on failure
and the next frame can retry. See [the mesh contract](../../docs/design/SDL3_MESH.md)
for clipping, presentation transforms, limits and recovery. Private-Xvfb software
readback tests cover pixels and injected failures; physical GPU and other OS
drivers remain separate validation requirements.

Use `cui_sdl3_render_capture()` to save a BMP before presentation while framebuffer
contents are defined. The lower-level `cui_sdl3_save_bmp()` reads the current
framebuffer; do not rely on its contents after `SDL_RenderPresent`.

Validation on the development machine: SDL3 3.4.16, Linux Xorg with SDL `opengl`
driver, and SDL dummy video with `software` driver. Other platforms and Wayland
require their own runtime validation. The adapter does not provide native
accessibility bridges, pen translation, GPU resource sharing or image commands.
Touch routing and composition have injected SDL service tests; these are separate
from real touchscreen and OS candidate-window acceptance.

Frame scheduling: call `cui_sdl3_frame_delta()` immediately before each submitted
frame to measure monotonic elapsed seconds (first call is zero). Presentation
already requests vsync; an additional fixed sleep reduces the achievable refresh
rate. When Core has no redraw demand, `cui_sdl3_wait_events(backend, timeout_ms)` sleeps
until input or the caller's deadline, retaining the wakeup event for poll. Idle
waits reset the frame clock so a newly triggered animation starts at its first
frame rather than skipping the time spent idle. Run
`cui_sdl3_poll()` after rendering and before an idle wait to apply the latest
text-input focus and caret, then again after waking to dispatch input. Keep
submitting frames while `cui_needs_redraw()` is true, including animation demand.
The examples cap idle waits at 250 ms; applications with external timers should
choose their nearest deadline and explicitly invalidate Core when their model
changes. Threaded producers can arrange an SDL event wakeup on the main thread.
