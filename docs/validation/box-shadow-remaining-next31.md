# Remaining BoxShadow contracts after Next30

Read-only baseline `534a9db2a96b2cf4760d76f61fd9d4fb52ba184a`; pinned gpui-component 0.7.1 commit `87d10ae5e1299d1be18670a37570c5402f952e34`. Only this audit and its JSON companion are changed. This audit does not certify a complete BoxShadow family or native GPUI image identity.

The smallest next production slice is **correcting source operation ordering and physical covering in the existing drop primitive**. Two accepted-input differences are reproduced below. Inset support should follow separately; no inset production API is approved by this audit.

## Public source contract

Pinned `gpui-pre 0.3.8/src/style.rs:349–393` exposes `BoxShadow` with color (`Hsla`), pixel offset, blur radius, signed spread radius, and `inset: bool`. `BoxShadow::new(offset_x, offset_y, color)` requires the offsets/color and sets blur/spread to zero and inset to false. Builder methods replace blur/spread and mark inset true. There is no `Default` implementation for BoxShadow. Default Style uses an empty vector (`style.rs:808`), not an implicit blurred shadow. `scene.rs:574–590` exposes the lower-level renderer Shadow primitive, including separate element/hole geometry; it is not a second constructor requirement for CUI users.

Public Styled shadow methods are generated by `gpui-pre-macros 0.3.8/src/styles.rs:384–490`. `shadow(vector)` replaces the complete list; `shadow_none` clears it. The named presets are convenience list factories. These exact source values must not be confused with the component's deliberately halved CSS blur conversions:

| Public preset | Ordered `(offset_y, sigma, spread, black alpha)` layers |
| --- | --- |
| 2xs | `(1, 0, 0, .05)` |
| xs | `(1, 2, 0, .05)` |
| sm | `(1, 3, 0, .1)`, `(1, 2, -1, .1)` |
| md | `(4, 6, -1, .1)`, `(2, 4, -2, .1)` |
| lg | `(10, 15, -3, .1)`, `(4, 6, -4, .1)` |
| xl | `(20, 25, -5, .1)`, `(8, 10, -6, .1)` |
| 2xl | `(25, 50, -12, .25)` |

Every offset_x is zero. All preset layers are non-inset. CUI's existing custom drop lists can express these visible configurations within its bounds, but CUI has no matching named preset factory. That is an API convenience gap, rather than an absent raster capability.

Component `styled.rs:59–125` contains **private** popover/toast/raised factories. Their helper names do not create mandatory public CUI APIs. Their consumer appearances are real requirements: popover uses ring plus `(4,3,-1)` and `(2,2,-2)` black layers; toast uses `(10,7.5,-3)` and `(4,3,-4)`; raised tab uses `(1,1.5,0)` and `(1,1,-1)`. `notification.rs:433,495,528`, `tab/tab_bar.rs:260`, and `popover.rs:101` consume them. This audit does not certify those other CUI owners merely because the generic drop primitive can express their layers. A search of the pinned component/base crates found no `BoxShadow::inset()` consumer; inset remains an explicit public GPUI styling contract.

## Source geometry, phases, and masks

`style.rs:706–740` clamps original corner radii to half the original minimum dimension, paints non-inset shadows, paints background, then paints inset shadows. Children run in the continuation; ordinary borders follow the continuation. Each phase preserves the supplied vector's relative order while filtering the other kind. A mixed vector is therefore not one unconditional paint sequence. `elements/div.rs:2543–2553` applies element opacity around Style paint but installs the element's own child-overflow mask inside the continuation. Both shadow phases see the current ancestor mask, before that child-only mask.

`window.rs:4424–4513` derives each rectangle in this order: offset the original bounds, dilate their origin and size, then cover the resulting rectangle on the device grid. `geometry.rs:1067–1073,1323` makes the far edge **derived origin + derived size**. `window.rs:3196–3205` floors near edges, ceils far edges, then clamps far edges to at least the corresponding near edge. It does not first discard a logically zero/negative dimension. Mask covering follows the same rule.

For non-inset shadows, dilation uses positive signed spread and radii remain the original clamped radii. Geometry extends three physical sigmas beyond the covered shadow rectangle. `scene.rs:88–94,235–238` culls against that unblurred covered rectangle and the current covered ancestor mask, so a tail-only intersection is excluded.

For inset shadows:

- The hole is offset original bounds dilated by **negative** signed spread. Positive spread shrinks the hole; negative spread grows it.
- Hole radii are `max(original_clamped_radius - spread, 0)`, then scaled. Source does not perform another radius clamp in the shader.
- Element bounds are covered separately; element radii retain their original clamp and physical scale. Hole and element quadrant selection are independent when offset/asymmetric corners differ.
- Vertex geometry is the covered **element**, not hole bounds expanded by three sigma.
- Fragment coverage is `(1 - blurred_hole_coverage) * rounded_element_coverage`. Both sigma-zero SDF coverage ramps use the source one-physical-pixel ramp.
- Scene culling still uses `Shadow.bounds`, which is the **covered hole**, not the element. An empty covered hole, or a hole disjoint from the current mask, is culled even when the element intersects that mask. This is the pinned behavior; a mathematical full-fill complement must not silently replace it.
- The Gaussian hole evaluation has no rectangular three-sigma X cutoff imposed by vertex geometry. Reusing CUI's drop sampler's hard outside-support return would change the complement. The four vertical samples still use the source finite Y integration range.

Source evidence is shared WGPU `shaders.wgsl:977–1046` and Metal `shaders.metal:462–555`. WGPU storage, WebGL, and subpixel variants concatenate this shared logic (`wgpu_renderer.rs:23–45`). Sigma-zero unrounded SDF uses the explicit `max(q.x,q.y)` fast path (`shaders.wgsl:362–379`); inset must preserve it rather than treating a square hole as an arbitrary Euclidean rounded-distance case.

## Reproduced existing drop differences

A strict-C11 external probe executes the frozen **standalone Effects header**, with no Core implementation/library, and independently calculates the pinned offset/dilate/cover operation order. The JSON stores its complete source, SHA256, and output; external artifacts are preserved at `/home/matteo/.cache/cui-validation/shadow-remaining-cover-probe.{c,log}`. These are source-derived geometry proofs plus actual CUI query execution, **not** native GPUI renderer executions.

| Input at scale 1, origin 0 | Source covered width | CUI covered width |
| --- | --- | --- |
| x=`4000.1001f`, width=32, offset_x=1.5, spread=`-.6f` | 32 | 31 |
| x=0, width=`1.0001f`, offset_x=4096, spread=`.0001f` | 2 | 1 |
| x=16384, width=`1.0001f`, offset_x=4096, spread=`.001f` | 2 | 3 |
| x=`20.25f`, width=1, offset_x=0, spread=`-.6f` | 1 | 0 |

The first three have positive derived logical width. CUI `src/effects/cui_effects.c:shadow_geometry` recomputes the far edge as an algebraic expression in the original fields, changing f32 cancellation/ceil boundaries. The final row collapses to negative logical width: source derived origin is about 20.85, size about -.2, and far about 20.65. Covering produces `[20,21)`, not empty. With the same y/height=1 inputs, its covered rectangle is 1×1. Source Scene sees a positive rectangle and inserts it against an intersecting mask; the sigma-zero drop vertex quad has positive dimensions and its center fragment has full coverage for radius zero. WGPU submits every nonempty shadow instance range (`wgpu_renderer.rs:1532–1537,1735–1758`), and Metal does likewise (`metal_renderer.rs:856–899`); there is no second logical-negative-size rejection after Scene insertion. CUI discards it before covering. More-negative dimensions can instead cover to zero, and must still succeed without paint.

The 1,620-case bounded probe found 17 positive-dimension width differences and 257 logical-empty width differences. These are matrix evidence, not prevalence estimates. The public Core bounds helper also currently decides logical collapse early; its conservative metadata must be reviewed with the raster correction. Existing documentation's blanket “collapsed negative spread paints nothing” is too broad for the pinned pixel-covering behavior.

## Recommended bounded slices

First, correct the existing shared drop geometry without adding public fields: materialize offset/dilated origin and size with source f32 operation order, derive far from those values, and clamp covered far to near **after** floor/ceil. Preserve original-radius clamping, finite/domain validation, sigma threshold, capacity atomics, source unblurred culling, command order, ancestor opacity, and all adapter paths. Validate cache normalization against the corrected actual covered geometry; normalized translation reuse must not reintroduce an algebraic recomputation. Add before-fix regressions for the cases above and both axes, fractional/DPR origin, strongly negative spread that truly covers empty, source mask culling, byte pixels, and copied/preflight failure behavior. The original accepted finite limits remain explicit; this does not expand arbitrary-transform or tiny-sigma support.

Then deliver inset as a complete capability across Core, pure Effects, and all five consumers, rather than an unused flag. One portable proposal is:

```c
typedef enum { CUI_BOX_SHADOW_DROP = 0, CUI_BOX_SHADOW_INSET = 1 } cui_box_shadow_kind;
typedef struct { cui_drop_shadow layer; cui_box_shadow_kind kind; } cui_box_shadow;
typedef cui_drop_shadow_paint cui_inset_shadow_paint;
bool cui_set_box_shadows(cui_context *, const cui_box_shadow *, size_t, cui_corner_radii);
bool cui_prepaint_inset_shadow(cui_prepaint_writer *, const cui_inset_shadow_paint *, bool deferred);
```

Append a value-owned inset command and checked inset query/sample/raster operations; keep every existing drop declaration and command value unchanged. The new raster metadata should expose checked physical covered hole and element bounds plus logical raster placement/dimensions. This avoids adapter/JS double recomputation and makes the pinned hole-culling rule implementable. This is an API proposal, not an approval to add declarations.

The generic setter replaces a copied list of at most eight **total** layers, partitions it at emission around the surface, and validates every enum/layer/radius before mutation. Zero count clears both phases. The legacy drop setter remains drop-only and replaces the same list, so a later legacy call cannot leave stale inset layers. New zero kind means DROP. Old NULL/no-style Chart behavior and bare tooltip behavior remain exact. Inset support does not require adding a speculative inset Theme popover layer: the source popover is drop-only.

Use the same bounded scale/origin/caster/offset/spread/sigma limits unless a narrower inset domain is justified and explicitly checked. Query/sample/raster/setter failures must preserve published output/storage/state. Share source numerical code through private helpers without making standalone Effects require Core implementation. Separate the internal hole convolution from drop vertex-support clipping. Cache keys must include kind, both checked geometries, all four radii, source phase, actual transform and color; copied values must survive caller destruction. Pin every prepared resource through the frame. Retain the combined 64 MiB active owned pixel-cache bound and all existing raster/command/clip capacities.

Prepare every required raster/texture before target dimension assignment, clear, or GPU swapchain acquisition. Preserve legal GPU post-acquisition failure submission. For Canvas, continue actual-transform queries, expiring prepared-frame lifetime, and physical covered-mask draws with ordinary clips suspended/restored. Insets must use the full covered element as raster domain and the covered hole for insertion culling, not the drop tail domain.

Required evidence for that later slice: asymmetric corners/offsets; positive/negative spread; sigma-zero complement and Gaussian falloff; complement beyond the hole's three-sigma X range; independent element AA; empty/disjoint covered-hole culling; mixed-list phase order; child-overflow/ancestor opacity; value copying; invalid/budget rollback; cache phase/resize/translation; meaningful software pixels and actual SDL Renderer pre-Present, SDL GPU, Sokol and DPR1/2 Canvas readbacks. Gaussian math should be checked against an independent convolution/reference where appropriate. Native GPUI platform image identity requires a separate actual source-renderer comparison.

## Fidelity and validation boundaries

Next30 provides consumed drop commands in Software, SDL Renderer, SDL GPU, Sokol and Canvas, standalone Effects query/sample/raster, copied Core/prepaint layers, and real three-layer Theme projection in both opted-in Chart tooltip consumers. Previous integration evidence proves those paths; this read-only audit does not rerun all native adapters/browsers or promote their other owners. CUI retains bounded eight-layer/raster/cache limits, RGBA8 color quantization, and explicit unsupported nonuniform transforms/small-positive-sigma cases. Native shader transcendental rounding, target formats, Hsla conversion, AA, color spaces, and Metal/WGPU image identity remain unverified platform boundaries.

For this isolated baseline, strict-warning portable build passed (404 build steps, native adapters disabled). Complete CTest passed **131/131**, exit 0. The external source-order probe compiled with strict C11 warnings and exited 0. Exact cached 0.3.8 crate archive SHA256 values match pinned Cargo.lock; every inspected extracted source file was byte-compared to its verified archive. Package/file hashes and source locations are recorded in the JSON. No production/global/manifest/distribution edits were made.
