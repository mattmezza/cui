# Element shadow ownership coverage: 78-family source audit

Audit baseline: `b553c8bb`; catalog authority [gpui-parity.json](../gpui-parity.json).
This is a read-only ownership checkpoint, not 78-component acceptance evidence.
Subsequent candidate slices add [six typed builder roots](../BRIDGE_SHADOWS.md)
and [opt-in C selection indicators](../NAMED_SELECTION_INDICATORS.md); the matrix
below deliberately preserves its stated baseline rather than counting those
later slices as acceptance of every family.
All 78 catalog families remain open for complete shadow coverage. Source references
identify current paint sites; the linked public header on each family is the
catalog authority. Additional additive headers are noted below.

The first C slice styles an already submitted, current-frame, non-layout-only
**named box**, including portals, through `cui_element_set_box_shadows` and
`cui_element_set_shadow_preset` ([contract](../../include/cui/cui.h#L679),
[implementation](../../src/core/cui.c#L2155)). It does not manufacture a component
root, address anonymous nodes, retain styles across frames, or shadow glyph/mesh
silhouettes. Apply after the actual box submission and before `end_frame`, never
from measurement/prepaint/diagnostics. Callbacks may submit different owners;
absence, virtualization, collapsed views and layout-only measurement reject.
Styling a transparent layout row is technically possible but is not equivalent
to styling its inner painted surface.

Codes in the C column describe **source-level eligibility**, not tests of that
family: **R** = caller-supplied named root/box; **P** = public named parts or
conditionally emitted portal; **I** = internally named owners without supported
public paint-ID mapping; **E** = justified host/data/no-paint exception. Private
XOR/hash IDs are recorded as private: copying their constants is not a public API.
For each R/P entry the first C seam is implemented, while the listed remaining
parts are not delivered by that seam. There is **no retained bridge/Python/JS/TS/
Go/Rust element-shadow authoring facade at this baseline** for any row. The
six-kind binding worker and opt-in Checkbox/Radio indicator worker are in flight;
their future work is not counted here. Existing built-in default shadows and
style callbacks are not general element-shadow coverage.

## Public-part authority and important boundaries

The getters above are declared in the family's linked header, except source
Label [`cui_label.h`](../../include/cui/cui_label.h), source Stepper
[`cui_stepper_visual.h`](../../include/cui/cui_stepper_visual.h), and textarea
viewport reused by Editor [`cui_textarea.h`](../../include/cui/cui_textarea.h).
Numeric part meanings are explicitly listed at
[`cui_numeric.h:52`](../../include/cui/cui_numeric.h#L52); NumberInput part0 is used
by the painter but omitted from that listed-part contract and needs documentation
before promoting it as a consumer promise. Surface parts are documented at
[`cui_surface.h:164`](../../include/cui/cui_surface.h#L164); Settings exposes a generic helper
at [`cui_settings.h:148`](../../include/cui/cui_settings.h#L148) but does not document
its role-number meanings; Sidebar has the same generic-helper limitation. A public helper
returning an interaction ID is not proof that every mode submits a box there;
verify the particular painter/mode in the evidence column. A bounds getter alone
also does not establish a current-frame owned paint box.

Notification is the clearest remaining ownership gap: its logical notification
key/type is converted by a private function to a card paint ID, there is no
submitted box at the supplied notification scope ID, and fully hidden cards are
layout-only. Root View, in contrast, really creates a named root through Base;
its facilities are separately owned. Clipboard, Focus Trap and Theme justify no
invented visual roots; applications can decorate their real enclosing controls.
Chart/Plot/Icon/Image expose rectangular owners; this is box shadow ownership,
not vector-path/raster alpha silhouette shadowing.

## Next independent slices

1. **Already public identities:** Switch track/thumb, Badge indicator, OTP cells,
   Input/Textarea viewport, Calendar/Time/Color controls, and explicit Table
   rows/cells. Add focused current-frame ownership, mixed DROP/INSET ordering,
   clipping and clear/invalid-transaction tests, then add narrowly scoped builder
   part targeting. Do not duplicate the six-kind facade worker's owned roots.
2. **Compound painted surfaces:** Bubble's actual surface/reactions, Message and
   MessageScroller cards, Attachment media/treatments, Notification card/actions.
   Add getters with distinct logical-key versus paint-ID contracts, conditional
   submission guarantees and layout-only rejection; do not substitute outer rows.
3. **Anonymous painted indicators:** Slider thumb/fill, Progress fill, Rating star
   artwork, visual-navigation Stepper circles/connectors, scroll thumb and Resizable visible handle
   line. Design opt-in names preserving legacy command streams; Checkbox/Radio
   indicators are already assigned elsewhere and excluded from this slice.
4. **Structured collections:** List/Menu/Select/Combobox parts, Tabs bar/panel/
   underline, Accordion/Collapsible panels, Tree/Sidebar/Settings/Dock sections.
   Publish only stable emitted-part mappings, with collapsed/virtual/portal tests.
5. **Document and raster owners:** Editor gutter/completion/find controls,
   TextView block/action surfaces, Chart/Plot tooltip frames. Separate meaningful
   rectangular controls from command-only marks/glyphs; a per-primitive API would
   be a separate design, not implied completion of this box seam.

Completion needs all-family ownership decisions plus headless behavior/painter
proof and matching consumer/binding documentation. This audit changes no public
API, painter, manifest, generated resource or test; no compile or native window
was run. It deliberately leaves the complete-coverage item unchecked.
