# Optional pinned regex provider

This backend is separate from default C11 CUI builds. It implements the portable `cui_text_match` ABI with source Regex1.13.1 admission and capture-free regex-automata0.4.18 PikeVM matching. See `docs/INPUT_REGEX.md` for Input ordering, lifetimes, limits and proof.

`pin.json` records exact source Cargo.lock crate archives, official Rust1.85.1 manifest/toolchain archives and the private patch SHA. `Cargo.lock` is a separate frozen path-dependency build lock; archive checksums remain authoritative. `cache.patch` only adds bounded fallible capture-free cache preparation; original upstream APIs are unchanged. The patch is not a general fallible capture API. All external sources remain in the caller's private cache, never vendored binaries or global installations.

Use an already verified complete official Rust1.85.1 prefix with matching target std. `scripts/build_regex.py --cache CACHE --toolchain PREFIX [--archive-dir VERIFIED_ARCHIVES] [--target wasm32-wasip1]` verifies every crate archive before extraction and the patch/lock digests, then builds offline/locked with private CARGO_HOME. With archive-dir missing, the script may fetch only pinned checksum-verified crate URLs. The script never installs a toolchain, changes rustup or invokes a default Cargo registry download. Target std must match the exact compiler. The toolchain receipt documents verified official acquisition; the supplied installed prefix is trusted caller-owned tooling and is checked for exact version/commit.

Source/parser compilation and Arc ownership creation may use infallible Rust allocation; OOM can terminate the process. Session creation/rebinding uses seven fallible cache reservations plus one fallible handle allocation. Match performs zero allocation. Native ordinary panics are caught at C entrypoints, but a host's default panic hook may print before catch; the backend neither logs candidates nor replaces a global hook. WASI panic recovery is unsupported. Handles/leases must be valid, externally synchronized, and used on one thread; forged pointers and direct caller writes are not protected.

Native Linux archive link dependencies are taken from Rust1.85.1's `native-static-libs` receipt: gcc_s, util, rt, pthread, m, dl, c. WASI reports libc only. Do not copy the Linux dependency list to another target. `backends/regex/CMakeLists.txt` is a standalone strict consumer harness accepting prebuilt regex/Core archives; it never invokes Rust. Root optional OFF-by-default registration, relocatable install/package targets and platform-specific CI are integrator-owned. No native Windows/macOS binary support is claimed by the Linux receipt.

Distribute the applicable notices under `licenses/` with optional artifacts: MIT chosen for alternate-license crate dependencies, Rust MIT/Apache notices and its complete official COPYRIGHT inventory. Root's dependency registry/install notices remain separate registration work. No source Input-family completeness claim follows from this optional matcher slice.
