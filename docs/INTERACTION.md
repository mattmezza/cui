# Interaction and touch routing

Core accepts mouse, touch, and pen pointer events. Existing zero-initialized
`cui_event` callers remain mouse callers. Touch adapters supply a stable
`pointer_id` until up/cancel, paired with portable `pointer_device` (zero
when the host has no device namespace). SDL preserves both `touchID` and
`fingerID`; identical finger IDs on two devices remain separate contacts. Core retains at most 16 contacts; excess contacts
are ignored. The public queue accepts 256 events per frame; separate bounded
512-event dispatch storage reserves room for every possible touch-capture
cancellation without dropping queued events. SDL finger coordinates are normalized by SDL and converted to
logical window pixels. The browser uses PointerEvents and pointer capture,
with `touch-action: none` on the canvas. Both adapters suppress compatibility
mouse clicks generated by touch.

One contact presses and taps through the ordinary focus/activation path.
Movement beyond eight logical pixels prevents tap activation; ordinary control
drag events remain available when no scroll/viewport owner claims the gesture.
Sliders, scrollbars, and focusable Separator resize handles retain pointer
drag ownership over their scroll ancestors. A custom draggable ID can use
`cui_set_touch_drag_priority(ui, id, true)` after registration; this preserves
its other semantics and takes priority over ancestor scroll/viewport pan.
Cursor selection does not affect drag policy. Pan takeover sends a targeted
Cancel event to the formerly pressed control before later queued contacts,
clearing retained selection/drag flags. A second contact cancels primary activation. Lifting one finger does not turn
the remaining finger into a new tap. Cancel/focus loss clears capture.

Scroll owners accept touch scrolling by default, or can opt out using
`touch_scroll_disabled` in semantic details. Once the eight-pixel threshold is
crossed, touch moves become precise `CUI_EVENT_SCROLL` events. Their deltas are
logical pixels with the same sign convention as wheel input. The initially
hit owner is retained by ID; routing can chain only to its actual ancestors
when its configured range reaches an edge. Hit routing respects clipping,
modal scopes, disabled owners, and higher interactive portal layers. Scroll
end/cancel events carry zero deltas. Reducers must use one pixel per precise
delta instead of their ordinary wheel line size. There is no inertial fling. Internal contact subtraction, centers and pinch
distances use double intermediates; generated deltas/scales saturate to the
finite float range. Non-finite input contact positions are ignored while
cancel can still terminate their lifecycle.

Viewport panning and pinch zoom are explicit opt-ins, independent of scrolling:

```c
cui_id plot = cui_id_from(ui, "plot");
cui_rect previous_bounds = cui_bounds(ui, plot);
size_t count;
const cui_event *events = cui_frame_events(ui, &count);
for (size_t i = 0; i < count; i++) {
    if (events[i].type != CUI_EVENT_GESTURE ||
        cui_event_target(ui, i) != plot || cui_event_consumed(ui, i))
        continue;
    cui_plot_pan(&scale, events[i].dx);
    cui_plot_zoom(&scale, events[i].gesture_scale,
                  events[i].x - previous_bounds.x);
    cui_consume_event(ui, i);
}
cui_plot_view(ui, plot, &theme, &view);
cui_set_gestures(ui, plot, true, true);
cui_set_cursor(ui, plot, CUI_CURSOR_GRAB);
```

`gesture_scale` is relative to the previous contact positions (one for pan
or end/cancel); `x/y` are the current center in window coordinates. `dx/dy`
are center movement when pan is enabled. `scroll_phase` carries started,
moved, ended, or cancelled. Pinch requires exactly two contacts owned by the
same viewport. Zoom is disabled unless `gesture_zoom` is explicitly enabled.
The gallery Plot opts in and applies both transformations to its scale.

Every registered interactive ID can use the shared hooks after its component
has built, including IDs inside compound controls:

```c
cui_id button = cui_id_from(ui, "run");
cui_theme styled = theme;
cui_interaction before = button_state; /* Caller-retained state from last frame. */
if (before.pressed) styled.primary = theme.danger;
else if (before.hovered) styled.primary = theme.info;
if (cui_button(ui, button, &styled, cui_string("Run"), false)) run_action();
cui_set_cursor(ui, button, CUI_CURSOR_CROSSHAIR);
button_state = cui_interaction_state(ui, button);

cui_id toggle = cui_id_from(ui, "pin");
cui_toggle_ex(ui, toggle, &theme, cui_string("Pin"), &pinned, NULL,
              cui_toggle_options_default());
cui_set_cursor(ui, toggle, CUI_CURSOR_HELP);
cui_interaction state = cui_interaction_state(ui, toggle);
```

`cui_set_cursor`, `cui_set_gestures`, and `cui_set_touch_drag_priority` change only their named fields and
preserve the component's scroll range, role, focus behavior, relationships,
and accessibility details. Apply them each frame after the component.
`cui_interaction_state` does not register semantics or consume activation.
It reports hover, pressed, focus, focus-visible, and activation for an ID
already registered in the current frame (previous frame when outside a frame).
Hover follows clipped/modal hit visibility and can apply to passive registered
viewport IDs. Pointer activation is a tap/click released over its captured
control, or the existing keyboard activation. A queried activation remains
visible after `cui_interact` consumes it; explicit
`cui_cancel_event_activation` removes it. Build a component before querying it during a frame. For styling before its
build, query the preceding completed frame and retain the result in caller
state. `cui_interact` remains the registration/activation-consuming API.

Built-in cursors include default, pointer, text, horizontal/vertical resize,
move, not-allowed, crosshair, grab, grabbing, zoom-in, zoom-out, wait, and help.
Browser mappings use matching CSS cursor names. SDL has no corresponding
system cursors for grab/grabbing, zoom, or help: its fallback is move for
hands, crosshair for zoom, and default for help. Its cursor cache is bounded
by the built-in enum count and is destroyed with the adapter. Caller-owned
custom RGBA cursor images/hotspots are not implemented by this API.
