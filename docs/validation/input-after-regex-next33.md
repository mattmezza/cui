# Input after regex: pinned-source audit and next slices

Proposal only. Audited CUI commit `12e183826ed39de0419ae2916091c41e52eed29b` against gpui 0.7.1 commit `87d10ae5e1299d1be18670a37570c5402f952e34` in `/tmp/cui-gpui-reference`. This is not a complete Input parity receipt. No production behavior changes accompany this document.

## Source boundaries

The source `crates/base/src/input/base/state.rs:10500–10630` single-line implementation exposes password masking, compiled regex, custom validation, number stepping/min/max and loading setters. The shared `mask_pattern` builder at 3565 is not confined to that implementation; CUI's unsupported multiline formatting is an explicit limitation, not evidence that the source lacks the builder. Source multiline `searchable`/`set_searchable` at 10636 onward controls the panel and Ctrl/Cmd-F interception: textarea defaults off, code editor on. Turning it off still permits engine search and lets the shortcut bubble. A single-line search panel is not a missing mandatory Input behavior.

Source Enter at `state.rs:1970` inserts a newline in multiline mode unless submit-on-enter intercepts plain Enter; Shift-Enter remains an insertion path. CUI's ordinary single-line Up/Down behavior and popup delegation have already been addressed. Multiline editor indentation, multiple cursors and search UI must be assessed as their own composed controls rather than inferred from edit-engine availability.

Inline-token insertion (`base/inline_tokens.rs:324–355`) rejects active composition, code-editor mode, masked/secret content and non-NONE format masks. Plain Input and textarea may insert tokens with custom/regex validation. It builds the whole prospective value, requires normalization to leave it unchanged, and rejects an invalid candidate directly; this operation does not use invalid-old healing. Seed installation has a different, weaker mode filter and can drop unsupported tokens. CUI's checked matcher currently rejects inline tokens and multiple selections; that is a documented CUI gap, not the source rule. Existing token metadata/atomic edit APIs alone do not prove custom chip painting, hit testing or activation parity.

Selected ranges (`state.rs:3021` and following) are ordered UTF-8 byte ranges. Source setters normalize token boundaries, clip start left and nonempty end right, reset reversed/word-drag state and extend from the clipped start. Select-all collapses extra cursors and breaks undo coalescing. Blur deliberately retains selection for application-menu copy (`state.rs:3397`). CUI `cui_edit_select` (`src/base/cui_edit.c:3791`) instead rejects non-boundary/out-of-range endpoints. Keep that strict API; source-style clipping would be an additional opt-in helper, not a weakened legacy contract. CUI's single-selection IME limitation remains explicit.

## Composed chrome and lifecycle gaps

`crates/component/src/input/input.rs:719` shows clear only when cleanable, editable, not loading, nonempty and single-line. Loading is a spinner at the right; `presentation.is_editable` excludes disabled/readonly, not loading. Loading must not silently prohibit typing or manufacture a busy accessibility contract. Suffix order is loading, mask toggle, clear, then caller suffix. Prefix/suffix are arbitrary elements, not merely strings; disabled reduces their opacity. Parent disabled captures pointer down. The reveal button (`input.rs:476`) is non-tab-stop and has no explicit readonly guard: readonly forbids value edits, not necessarily revealing the unchanged value.

Clear (`clear_button.rs`, `state.rs:2073`) replaces the value with empty, resets selection/scroll, then focuses the input. CUI currently has no equivalent composed clear/loading/prefix/suffix/reveal builders. The existing controlled `.masked` option is not an owned reveal toggle. Source mask/copy privacy and the completed CUI secure presentation preflight must be reused, not bypassed by a new child button.

Source emits `Change`, `Focus`, `Blur`, and `PressEnter { secondary, shift }` (`state.rs:126`). Focus starts blinking; blur breaks coalescing, stops blinking, clears transient hover/completion/touch state and, for number inputs, may clamp through validation (`state.rs:3390–3425`). A context-menu-open blur is suppressed. CUI Input reports changed/submitted and already tracks focus for history/composition; it does not expose this complete event contract or modifier-bearing submit. Callback events must follow adoption, never substitute for acceptance predicates.

Source `tab_index` builder (`input.rs:362`), context menu, clean-on-Escape and platform-specific bindings remain separate refinements. Escape prioritizes menu, extra cursors, completion, touch selection and IME unmark before optional cleaning (`state.rs:2080`). Do not intercept popup Escape blindly. Source macOS Cmd line deletion/Alt word deletion and non-mac Ctrl word deletion (`state.rs:135` onward) require a host-selected policy or semantic action mapping; a portable Ctrl/Meta union is not proof of all platform bindings. Character-palette invocation is a host seam, not a portable engine operation. Async on-paste and content types beyond the supported secure-purpose subset remain unresolved; do not conflate them with regex matching.

## Prioritized complete implementation proposals

1. **Chrome plus lifecycle events.** Append zero-off cleanable/loading and explicit reveal policy options, caller-owned bounded prefix/suffix composition callbacks, stable parent-derived child IDs, and optional bounded event output. Preserve default layouts. Loading changes paint/clear visibility only. Clear uses checked whole-value replacement, final presentation preparation and one undo step; only successful adoption resets selection/scroll and refocuses. Rejection or resource failure leaves those states intact. Slot child focus must preserve source focus-ring containment without inventing mouse events. Events retain multiple accepted transitions without replay; reserve output capacity before an event whose notification retention is promised. Removed-control blur needs an explicit lifecycle/reset owner, because a widget that is never called again cannot discover its removal.

   Reveal requires a reviewed ownership choice: opt-in retained effective-mask state versus a result requesting a controlled caller change. Either prepares the desired current display before publishing mode, preserves logical text/history, destroys plaintext geometry when entering masked mode, and causes the existing Core purpose/generation bridge to rebind. Rebinding/model replacement resets retained state. Readonly reveal and disabled blocking need exact composed tests. No hidden allocations or arbitrary-element parity claim from text-only slots. Reuse existing bounded status motion sampling and finite host deadlines for the loading glyph; do not invalidate forever while inactive.

2. **Selection/actions and focus refinement.** Add a pure checked UTF-8/token-aware clipping helper and a reviewed semantic action/host shortcut policy, preserving strict legacy selection and zero-default shortcuts. Append tab index and modifier-bearing submit results; opt-in clean-on-Escape runs only after existing popup/IME delegation. Test interior multibyte endpoints, reversed selections, token boundaries, context-menu focus retention, focus removal/rebinding, Ctrl/Alt/Meta policies and repeat suppression. Selection-only actions must not invoke acceptance or create undo entries.

3. **Plain inline-token vertical slice.** Implement actual bounded token view spans, custom cell painting/hit/activation, clipboard representation and accessibility, then allow whole-candidate regex validation where source permits it. Token edits use their source direct rejection rule rather than invalid-old healing; IME-active/masked/secret/formatted/code-editor restrictions stay explicit. Retain owned or explicitly borrowed metadata lifetimes through frame/render caches; test source seed-vs-insertion differences, overlap, undo, removal, custom UI focus and capacity failure before mutation.

4. **Remaining specialized contracts.** Number blur/step behavior is distinct from NUMBER formatting. Multiline search panel belongs to Textarea/Editor, not ordinary Input. Async paste needs a model/revision/focus lease, cancellation and bounded caller ownership. Additional content-purpose builders require honest adapter capability reporting and host tests. These are subsequent scopes, not incidental additions to chrome.

## Acceptance and resource proof required for the next slice

Actual Core-composed tests must cover loading while typing, all clear suppression cases, same-frame child activation exactly once, custom prefix/suffix focus, clear one-Undo, readonly selection/copy, disabled rejection and focus/blur ordering. Include regex/custom/mask rejection and invalid-old healing without callback replay; IME UPDATE stays unformatted and COMMIT occurs once. Forced allocation, factory and caller-buffer failures must happen before document/history/selection adoption; secure toggles must never fall back to plaintext. Test all design sizes and native actual-font glyph/selection pixels, plus real Chromium bridge typing/composition/rebind. Headless engine assertions alone do not demonstrate composed chrome or host behavior.

Portable declarations contain no platform types. Caller workspace/event/slot capacities and alias spans must be checked before writes; callback reentry and mutation guards follow existing checked edit rules. Borrowed callback userdata must outlive its retained widget state; render caches deep-copy or retain immutable data under their existing contract. No mandatory Rust dependency is introduced by these future slices.
