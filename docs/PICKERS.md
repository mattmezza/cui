# Date and time pickers

`cui_picker.h` provides Calendar, DatePicker, TimeField and ColorPicker. Core date/time structures and base reducers contain no platform, theme or Clay dependencies. Styled wrappers use common box/text/portal commands and cached SVG icons. Selected dates/times and retained navigation state are application-owned.

Calendar renders one to three actual month grids, with configurable first weekday, selected date/range, minimum/maximum endpoints, disabled predicate and whole-widget disabled state. The grid model exposes 42 consecutive cells including neighboring dates and zero cells at Gregorian year boundaries. The legacy styled view leaves neighboring cells blank; opt-in presentation renders distinct selectable occurrences as described below. Canonical date IDs remain stable across navigation/reordering. Each day has a full ISO date semantic name by default, or numeric locale-formatted full date when a locale is supplied, disabled/selected details, and a roving Tab stop. The model supports years 1 through 9999. An invalid initial date defaults deterministically to 2000-01-01; applications provide their own current date.

Month/year buttons navigate by one/twelve months. Arrow keys move one day or one week, Home/End move to weekday-aligned row boundaries, and Control/Meta with arrows moves months/years. Disabled candidates are skipped with a bounded 366-attempt search. Navigation changes the displayed month when the cursor leaves the visible months. Enter/Space or a day pointer click selects the cursor/date. Range mode takes two activations, sorts reverse selections, and keeps a pending endpoint between frames; disabled predicates constrain endpoints, not every interior date. Navigation never implicitly changes selection. Styled cell size defaults to 32 logical pixels and is bounded to 20..128 pixels. Seven builtin locale tables and custom borrowed labels/order/separator are available through cui_date_locale. Arbitrary month counts and arbitrary source item styling remain unsupported; frozen Calendar does not implement week-number columns, hover-range previews or a dedicated arrow-key map.

The additive `cui_calendar_presentation.h` API enables independent month headers, a host-supplied today marker and selectable neighboring-day occurrences through `cui_calendar_ex`. Zero presentation options preserve legacy behavior. Use matching rebuilt headers/library, keep the canonical day ID for in-month cells and query neighboring occurrence IDs with `cui_calendar_cell_resolve`. DatePicker and typed CHANGE wrappers remain separate from these extensions. See [Calendar presentation](CALENDAR_PRESENTATION.md) for input ordering, policy checks, focus, borrowed lifetimes and explicit CUI range/recentering differences from frozen source. New presentation behavior is headless-tested; no browser or language-builder coverage is implied.

The base Calendar offers reduction and semantic submission separately, plus a combined convenience function. DatePicker uses this separation to close a selected popup before submitting its modal scope. Closing on selection, Escape, outside click or disabling restores a valid trigger focus; this avoids leaving a closed modal scope in the activation frame. It uses the same `cui_overlay` focus/dismissal state and `cui_popup_place` collision model as choice popups. Its actual calendar renders as a viewport portal beyond ancestor clips, flips/clamps to the supplied viewport, and confines Tab focus while open. Range pickers close only after the second endpoint. Trigger semantics report expanded/controls. Calendar day and weekday labels are centered in their cells; month/year navigation uses SVG chevrons and retains accessible navigation names. DatePicker shares this renderer and uses a centered trigger with a calendar SVG. The current appearance uses ISO labels, a selectable calendar, and placeholder text; editable date masks, clear controls, custom locale/date formats and preset ranges remain pending. Small viewports clip a calendar rather than resize or scroll it.

TimeField stores a valid 24-hour `cui_time` and displays segmented hours/minutes, optional seconds and optional AM/PM. Each segment has a name, numeric value/range and readonly/parent details; one active segment participates in Tab navigation. Left/Right changes segments, Up/Down wraps the active unit, Home/End selects its limits, and digit input advances after two digits. Two-digit drafts persist across frames. AM/PM accepts A/P or keyboard toggling. Twelve-hour display preserves the 24-hour model. Disabled/readonly suppress mutations. Strict standalone parse/format functions accept/emit ASCII `HH:MM[:SS]` and reject out-of-range units. Custom min/max times, typed separators, full-width normalization, configurable formats and native input/IME integration remain pending.

Meaningful tests exercise leap years and weekday grids over forty years, minimum/maximum/disabled dates, actual routed multiple-arrow navigation, weekend skipping, year controls, reverse range selection, all four themes, persistent segmented digits, hour/minute rollover, 12-hour periods and disabled/readonly behavior. DatePicker tests cover actual portal geometry outside a clipped parent, selection close with trigger focus restored in the same frame, seventeen trapped Tab events, Escape and outside dismissal. The same Calendar/TimeField event suite compiles with `CUI_PICKER_BASE_ONLY`, no theme/components linkage, and bare geometry; base drawing remains empty. Strict warnings, fully instrumented ASan/UBSan, and existing CTest pass before submission. Root owns build/distribution registration.

ColorPicker includes a retained HSV model controlled by application RGBA bytes, a two-dimensional saturation/brightness surface, hue and alpha controls, numeric RGBA channel sliders and up to 64 palette swatches. Arrow/Home/End keys adjust named channel semantics. Pointer capture survives separate down/move/up frames and is cancelled explicitly. Readonly/disabled suppress changes. HSV conversion handles negative/wrapped hues and sanitizes nonfinite components; strict `#RRGGBB[AA]` parsing and formatting are allocation-free. A 12×8 common-rectangle grid approximates the SV gradient and shows a selected-cell outline; hue uses 24 bands and alpha uses 16 bands. Channels display their numeric values and horizontal ranges. Palette clicks and external replacements synchronize HSV; achromatic channel edits preserve hue. The current widget lacks editable hex/channel text, exact continuous shader gradients, a native eyedropper and upstream popup presentation/options. It is an inline, real interactive color control rather than a claim of complete ColorPicker parity.

Color tests add 20,000 deterministic RGBA→HSV→RGBA and hex round trips, primary/wrapped-hue/nonfinite boundaries, channel/palette keyboard/pointer behavior, cross-frame captured SV release, readonly/disabled checks, semantic ranges, all themes and measured gradient geometry. The base-only flavor exercises the same color reducer without theme/components. Twelve-hour TimeField semantics expose the displayed 1..12 range; Home/End preserve AM/PM while choosing 1/12.

## Picking a screen color

The website's **Pick from screen** button uses the browser EyeDropper API. Select any screen pixel; Escape cancels without changing the controlled color. The chosen sRGB bytes replace RGB and preserve the current alpha. Unsupported browsers show an availability message. Navigation or disabling the component cancels an outstanding request. Screen access belongs to the host, so no browser or operating-system type enters CUI's public API.

Native hosts can open their platform picker from a button callback, then assign the returned color to their application-owned `cui_color` and schedule a frame:

```c
/* Run after your host picker completes successfully, on the UI thread. */
cui_color sampled;
if (cui_color_parse_hex(cui_string("#1A8F64"), &sampled)) {
    sampled.a = color.a; /* Optional: preserve the existing opacity. */
    color = sampled;
    cui_invalidate(ui);
}
/* The next cui_color_picker call synchronizes its retained HSV state. */
```

The browser requires a secure context and a user gesture; call `new EyeDropper().open()` directly in the click handler before awaiting anything or scheduling a C frame. A resolved `sRGBHex` can be parsed with `cui_color_parse_hex`; cancelled or rejected requests must leave the value unchanged. See the [Chrome EyeDropper guide](https://developer.chrome.com/docs/capabilities/web-apis/eyedropper) and [API specification](https://wicg.github.io/eyedropper-api/). CUI's native adapters currently do not implement an OS screen picker; applications provide that host capability.
