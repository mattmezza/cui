## Exact source consumer contracts

`crates/component/src/styled.rs:16–125` defines private helpers. They are not mandatory public CUI factory names. Their consumed appearances are requirements:

* Popover: ordered DROP layers `(x,y,sigma,spread,color)` are `(0,0,0,1,foreground with alpha .1)`, `(0,4,3,-1,black with alpha .1)`, `(0,2,2,-2,black with alpha .1)`. Strength clamps to [0,1] and multiplies each layer alpha. The foreground ring follows the theme foreground, not border/popover-foreground; dark themes can have a light ring. The sigma-zero layer is a filled expanded rounded rectangle under the surface, with original caster radii, not an outline. `ThemeStyled::popover_style`, lines186–194, applies theme popover background, popover_foreground text, these three layers, theme radius, and no ordinary border.
* Toast: ordered black DROP layers `(0,10,7.5,-3,.1)` and `(0,4,3,-4,.1)`, no ring. `notification.rs:421–440` uses popover background, an actual1px theme border, radius_lg, padding .875rem vertically/1rem horizontally and gap .75rem, then applies user StyleRefinement. This is distinct from public `shadow_lg` sigmas15/6. Icon kind controls Info/Success/Warning/Error colors; it does not change the shadow palette.
* Raised segmented TabBar indicator: `tab/tab_bar.rs:245–260` uses theme background, size-derived inner radius/height, and ordered black DROP `(0,1,1.5,0,.1)`, `(0,1,1,-1,.1)`. Pill/Underline indicators use their own backgrounds/lines without this raised shadow. The horizontal tab wrapper clips overflow (`tab_bar.rs:527`) and the inner strip scrolls (`:545`). The indicator owns the shadow caster: the selected label or whole trough must not supply the caster instead.

Tab branches are not interchangeable. Source standalone segmented Tab uses public `shadow_xs` on its inner element when `tab_style.shadow && !segmented_indicator_active` (`tab.rs:664,747`), so it has sigma2/alpha.05. While a segmented TabBar has not yet measured its shared indicator, the inline selected fallback uses public `shadow_sm` (`tab.rs:839–850`), sigma3/2 and alpha.1. After measurement the shared indicator uses the private compact raised layers above. Disabled segmented TabStyle leaves its shadow flag false (`tab.rs:297–308`); the shared TabBar indicator selector itself checks selected index/count, not the child's disabled flag (`tab_bar.rs:195–205`). A subsequent slice must preserve this exact branch distinction rather than apply raised layers to every selected or disabled pill. The source has no invented tab-loading shadow API.

### Enable, customization, opacity, and placement

Integration clarification: this audit preserves the earlier source inspection and pre-implementation probes. The tested Notification implementation separates transition alpha from stack visibility: shadow ink is `.1 * transition_alpha^4 * stack_visibility`, then Core applies ancestor opacity once. Stack visibility is not raised to the fourth power. Popover/Notification implementation evidence now lives in their component guides and dedicated actual-consumer tests; the missing-layer table below describes the historical audited baseline.

Popover defaults are appearance=true, open=false, anchor TopLeft, left-button trigger, no arrow and outside-closable=true (`popover.rs:136–155`). Appearance=false skips default background/padding/shadow, but `.refine_style(&style)` follows the default style (`:355–361`), so explicitly supplied user surface/shadows can still apply. Public Styled refinements customize actual surface properties. Default offset is .25rem plus optional .375rem arrow size (`:320–326`); base positioner resolves the anchor/side. The arrow uses the resolved background and foreground-derived ring on its two slopes (`:370–396`). The `appearance` method's comment also says outside dismissal is disabled; the actual component forwards `self.overlay_closable` independently at `:349`. Do not turn this documentation/code discrepancy into an invented coupling without a focused source behavior test.

Popover itself does not call `dropdown_popup` or install that helper's animation in its RenderOnce path. The private dropdown helper (`popover.rs:83–104`) separately supplies a150ms cubic enter, -8px initial top offset, element opacity delta and shadow strength delta cubed; it has no retained exit. Applying that helper's animation to every public Popover would invent behavior. Generic caller element opacity still multiplies shadows once through GPUI element opacity.

Toast transitions use400ms enter/200ms exit, cubic Bezier(.25,.1,.25,1), and96px placement-directed slide (`notification.rs:30–32,485–530`). Top placement slides from/away above; bottom from/away below; center has no slide. Shadow strength is opacity cubed; GPUI element opacity then multiplies layer ink again, giving effective `.1 * opacity^4` before inherited opacity. The animation explicitly replaces the shadow list after the base StyleRefinement, including at resting delta1. Do not promise arbitrary Notification shadow refinements survive that overwrite. Reduced motion adopts final values through GPUI animation handling. System-only delivery has no toast and thus no card/shadow. Closing content remains mounted through its transition. Arbitrary content/actions can contain loading or disabled children; there is no separate source Notification loading-shadow kind.

## Smallest complete next slice: consumed notification DROP styling

Recommend implementing the source two-layer toast appearance on the actual notification card, including fading, closing/inert and stacked/hidden geometry. No Core, Effects, renderer or public private-helper factory is needed. Use the existing value-copy node setter; the two layers are attached to the final card caster after geometry resolution, not separate expanding portals. Keep the source ordinary border above the surface/content. This bounded slice completes this shadow behavior, not Notification or Popover families.

Suggested compatibility API: append `cui_notification_shadow_policy` `{ LEGACY=0, SOURCE=1 }` and a by-value `shadow_policy` field to notification settings. Zero/default preserves the current path; Root gallery explicitly selects SOURCE after proofs. Init validates unknown policies atomically. Rendering must validate a caller-mutated policy before input reduction/state changes. Because the legacy return is a scheduling struct, expose a checked bool rendering entry with an output advance struct, or another explicit documented failure channel; do not silently accept invalid enums. Keep the current function/zero settings behavior. The production implementer should send the final exact checked signature before edits. Custom arbitrary shadow-list overrides are not required by the source animation branch and are outside this bounded proposal.

Source mode generates its two layers privately, without heap/VLA. Ink alpha is projected once from `.1 * final_visible_opacity^4`, with documented nearest byte quantization; existing externally inherited opacity is applied by Core once. Do not additionally set card opacity while leaving already-faded theme colors in place. If implementing owner opacity instead, change all source-mode local colors consistently and prove absence of double fading. The final visible opacity includes the current stack-visibility spring; source full resting ink is26. Both original layer orders/sigma/spread/radius must survive. Source mode must not emit the sixteen approximate shadow portals or duplicate a shadow beneath the exact pair.

Source-only style payloads are local values copied immediately by Core. Borrowed content/action strings/callbacks keep their existing state/frame lifetime contracts. No layer pointers may enter retained cache or deferred payload. Existing shared resource preflight,8 mixed layers/node,16M texels/raster,64MiB active owned cache, uniform-transform domain and explicit pre-clear adapter failure remain unchanged. The shadow primitive prepares all resources before target mutation; the styling slice must not weaken that contract. Existing callback side effects and owner state reduction are not magically renderer-resource rollback transactions. ROOT registers/regenerates global artifacts.

Proposed production ownership: status public settings/checked API and notification-only Base validator/Components render regions, focused NEW tests/guide; no Core/adapter/Theme changes. Popover and segmented TabBar follow separately with their respective style/arrow/refinement and measured-indicator contracts.

### Meaningful proof requirements

* Headless emitted values/order/caster/radii at rest, controlled enter/exit fractions and interruption; effective opacity0,.25,.5,1 with independent expected alpha, no duplicate approximate rectangles, finite quiescence and atomic invalid policy.
* Both light/dark/custom themes with popover/background/border roles deliberately distinct; Info/Success/Warning/Error colors leave black shadows unchanged. Loading custom content and disabled action children do not suppress decoration. Closing/inert/hidden stack items retain or suppress paint exactly as lifecycle requires; system-only delivery emits none.
* Software numerical/pixel comparison of two-layer compositing, translucent card showing under-surface contribution, original radii and spread, nested/root masks and viewport edges. Geometry resize/stack width/scroll must move the caster and cache correctly; no tail-only unblurred-mask intersection paint.
* Actual five-consumer DPR1/2 source-mode readback, byte-quantization bounds stated rather than native GPUI identity. Browser checks phase/frame signals, shadows inside/outside surface, current root Gallery usage and zero/pre-clear rejection without erased old pixels; no screenshot-only approval.
* Strict warnings, completed CTest, scoped ASAN/UBSAN and WASI before frozen handoff. Preserve before-failure probes and first failures. Gaussian kernel/native GPUI AA/color identity, general StyleRefinement, placement/arrow and other notification behavior remain explicitly separate.
