# Combobox observer implementation checkpoint

Scope: Base and Styled single-selection Combobox, reusing immutable shared selection types and the [approved selection contract](SELECTION_EVENTS_SLICE.md). Select/RadioGroup behavior stays unchanged; multi-selection and query/edit event facades remain outside this slice.

Add `cui_combobox_event_result { cui_selection_event_result events; cui_combobox_result legacy; }`. New `cui_base_combobox_events` and `cui_combobox_events` match their legacy argument lists followed by `cui_selection_handler`. Missing observer preserves editing/selection and returns zero callback count. The typed payload captures actual `previous/value/item`; CHANGE notification is not an owner-rejectable request. ACTIVATION reason denotes selection confirmation, including Enter; it does not assert a Core activation snapshot.

Append private observer/result parameters to the existing static Base combobox reducer. Legacy single/multi entry points pass no observer. The new Base wrapper initializes result bookkeeping and invokes that reducer once. At an existing Enter selection assignment, freeze actual frame/index/KEYBOARD facts, run the existing write/internal callback, capture the actual value, and notify only for a transition. Never synthesize HAS_ACTIVATION for this direct key path. Preserve single Enter loop break, later-text handling, filtering/scratch errors, matching count, query mutation and close timing.

The Styled renderer gets optional private forwarding arguments; legacy calls supply none. New forwarding delegates once to Base events, retains that count, then uses the existing private Select list observer seam for the popup-list phase. No duplicate Base observation and no replay/sorting of events. Existing `.legacy.changed` assignments, including popup-path overwrite, remain exactly as implemented. Notifications count actual callback invocations even when the final legacy result collapses transitions or a handler changes owner state.

Base input/query/Enter reduction precedes Styled popup-list reduction. Callback event indices can decrease across phases: retain truthful indices and phase order rather than promise global input-index order. Query-only edits, Enter without a matching candidate, navigation, external assignment and same-value confirmation emit no selection CHANGE. Genuine option activation snapshots are copied only if already available; otherwise retain real type/frame/index/source and omit HAS_ACTIVATION because list semantics normally register after reduction. Compound metadata target is the input; copied activation child target is unchanged. No early registration or Core routing change.

Current OPTION accessibility ACTIVATE is unsupported; accessibility FOCUS is supported but does not itself synchronize the retained list cursor. Test those boundaries and explicit keyboard navigation, not invented successful activation. Callback users/storage/resources remain borrowed through existing active boundaries; copied payload is pointer-free. Owner writes/later consumption affect subsequent reducer work, not recursive events. Active teardown/context destruction/reentrant submission remains unsupported. No scheduler, request hook, lifecycle/submit/query event or bindings allowlist is added.

Tests must exercise actual Base and Styled calls, independent query/selection ownership, both text-before-Enter and Enter-before-text cases, filtered-out selection, same-value confirmation, missing handler, scratch failures, pointer/touch and mixed-phase ordering, owner mutation/consumption, disabled/inert/omitted calls, explicit accessibility limits, payload lifetime and unchanged legacy choice regressions. Root owns registration/generation.
