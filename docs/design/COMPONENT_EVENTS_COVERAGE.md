This covers the exact 78 names in [the frozen manifest](../gpui-parity.json), not a parity promotion. The design request is tracked in `docs/design/COMPONENT_EVENTS_REQUEST.md` at this baseline. This document describes existing C APIs and implementation seams. It approves no new API.

## Reading the evidence

Each row has a public contract, implementation, and an existing focused test to inspect. These are source evidence and test locations, **not a claim that every event property in that row has a dedicated passing assertion**. No runtime suite was run for this documentation-only audit. In particular, general callback reentrancy, context destruction, arbitrary descriptor removal during dispatch, cross-family ordering, and every binding's callback ownership remain unverified unless explicitly documented below.

The grouping is by ownership and dispatch semantics, not visual similarity:

- **S**: synchronous reduction/operation or submission. A callback's presence does not make its handler retained. Payload pointers are borrowed unless a stronger copy contract is explicit.
- **R**: a model, resource, descriptor, or lifecycle snapshot retains handlers/users or borrowed inputs beyond a submission. The owner must keep them alive until their last use/teardown; the individual API determines that boundary.
- **F**: layout/prepaint/paint can invoke callbacks later in the current frame. Submission-only lifetime is insufficient.
- **Q**: explicit bounded queued delivery, distinct from synchronous UI reduction.
- **N**: noninteractive family-level exception. Render, validation, formatting, easing, resource-loader and host-service functions are not automatically component events. Interactive children retain their own contracts.

A bool may mean changed, activated, valid, opened a container, or successfully submitted. It is not a common event record. A typed result can aggregate a frame without specifying event count. Merely reading a returned C value has no dispatch effect; operations such as `take_result`, `update`, `pump`, `dispatch`, and `confirm` are actions, not passive getters.

## Verified distinctions that a common convention must preserve

1. **Request is not commit.** Checkbox source, controlled Slider, Switch/Toggle callbacks and Sidebar expansion permit application-owned values. RadioGroup has its own callback-versus-legacy-write rule. Returning an activation/change bool cannot establish that the owner accepted a proposal. See [Checkbox source tests](../../tests/unit/test_checkbox_source.c), [controlled siblings](../../tests/unit/test_controlled_siblings.c), [RadioGroup contract](../../include/cui/cui_radio_group.h), and [Slider phase tests](../../tests/unit/test_slider_controlled.c).
2. **Activation can have multiplicity.** [Button callback events](../../tests/unit/test_button_callback_events.c) and [implementation](../../src/components/cui_components.c) distinguish per-accepted-event callback dispatch from frame bool aggregation. Legacy `on_click` precedes the typed snapshot callback. [List reducer](../../src/base/cui_choice.c) invokes activation before confirmation; cancellation is independent of selection change. A blanket end-frame dispatcher would change observable ordering.
3. **Lifecycle may outlive the initiating call.** [Surface close](../../src/base/cui_surface.c) stores its close callback and delays actual close through motion; [Notification](../../src/base/cui_status.c) shallow-copies descriptors into entries (not an owned deep string copy). [Dock](../../include/cui/cui_dock.h) has explicit snapshot capture/dispatch and reconstruction/factory destruction, in addition to view callbacks. Dock's complete callback mutation/removal/reconciliation ordering needs a separate event trace audit before adapters are designed; this inventory does not certify it.
4. **Some rendering happens after submission.** [Plot/Chart current-frame contracts](../../include/cui/cui_plot_view.h) borrow state/data/users through deferred paint; [prepaint tests](../../tests/unit/test_plot_chart_prepaint.c) are relevant evidence. Typed Chart tooltip info/builders are callback-local; builder setters copy bounded strings, but borrowed data and raster writes remain external. Converting these to event listeners would conflate rendering and notifications.
5. **There is already a queued exception.** [Speech](../../include/cui/cui_speech.h) copies reports to bounded workspace and emits only from its explicit owner-thread pump, with generation-tagged sinks. It is not evidence that arbitrary component handlers can safely run on worker threads. The callback's transcript view still needs copying for deferred consumers.
6. **Validation/rejection has a narrower meaning.** [Input acceptance](../../tests/unit/test_input_acceptance.c) separates rejected edit from error/submission; the [Base contract](../../include/cui/cui_base.h) describes synchronous candidates and completion. Notification host send rejection is a transaction boundary. Surface decision false keeps it open. None of these return values means DOM-style propagation stop or platform-default prevention.
7. **Borrowed event is not always a copyable snapshot.** Button explicitly provides a pointer-free accepted snapshot. Slider carries a copied `cui_event` but only promises callback-local borrowing; TextView passes a borrowed event pointer and decoded URI. No common durable event ownership can be inferred from those three signatures.

## Bindings and host boundary

This matrix inventories public portable C, not 78 verified language event surfaces. The [C bridge](../../include/cui/cui_bridge.h) explicitly copies clicks into a bounded queue and language callbacks run after `step`; its native `run` callback has a separate deferred-destroy contract. That differs from direct C Button synchronous dispatch. The [Rust wrapper](../../bindings/rust/src/lib.rs) is a separate adapter; matching node names or constructors does not establish matching typed callback payloads, multiplicity, lifetime or controlled rejection. Every row's direct callback availability in Rust/Go/other generated bindings is **unknown in this checkpoint** until an explicit export/signature and callback-retention matrix is added. No proposed new event API is exported by this document.

Clipboard, TitleBar, Speech, image loaders and Root plugins are host/service boundaries. Their callbacks cannot be made portable network/OS implementations by renaming them as component events. Video/VideoControls are additive modules outside these 78 frozen families. Their supplementary inventory below does not add a 79th baseline entry.

## Design obligations and missing proof (proposals, not current guarantees)

The following is recommended work for the separate proposal; none is asserted as implemented:

- Define common naming and typed metadata while keeping activation, requested value, committed notification, submission and lifecycle distinct. Preserve the concrete double/ID/date/color/tri-state/text types; opaque `void *user` is context, not an untyped value payload.
- Specify each entry point's callback/result multiplicity, event ordering, snapshot point, disabled/loading/inert/omission behavior, and accepted input channels. Use existing pointer/keyboard/accessibility evidence; do not fabricate coordinates or source metadata for model operations. Current Sidebar header/footer are explicitly pointer-only.
- State handler retention, payload copying, scratch bounds, deferred access and removal/teardown rules. Default to no context destruction during dispatch unless explicitly supported; the bridge runner's deferred-destroy behavior does not grant that permission to portable C controls.
- Test callback-driven owner rejection, value changes, sibling removal, callback replacement, nested operation attempts, and shutdown. Distinguish supported mutation from rejected reentrancy rather than merely documenting whichever behavior happens today. Existing focused tests above are starting evidence, not blanket coverage of these cases.
- Keep propagation/consumption, owner acceptance, and platform default action separate. A generic capture/bubble system would require Core routing and lifetime design; current reducer order alone is not such a system.
- Offer one recommended application side-effect path. Preserve legacy callback ordering and mutation in wrappers; consuming both frame result and callback for the same action must not be the recommended pattern. Passive result reads must never replay callbacks.
- Audit exports and generated human/LLM references with the implementation. Binding adapters must explicitly preserve or document their queued timing differences and bounded-overflow behavior.
- For any optional async example, workers own jobs and requests, publish synchronized UI-thread completions, wake an idle host runner, reject stale generations, and terminate/cancel safely. No networking is needed in deterministic headless tests. This is a host example requirement, not permission for callbacks to block or for Base to depend on a codec/network runtime.

## Check against the parallel proposal

Reviewed `docs/design/COMPONENT_EVENTS_CONTRACT.md` at integrator commit `84376caa` without changing this audit baseline. Its additive facades, preserved legacy timing, separate acceptance/consumption, callback-local payloads and no generic bubbling match the source distinctions above. The following are architectural exceptions requiring explicit wording before implementation, not contradictions to hide:

- “Synchronous component-local dispatch” must exempt Speech's explicit pump and the bridge's queued language delivery. They are shipped behaviors, not candidates for silent retiming.
- “Handlers borrowed through submission” applies only to new immediate facades. Surface, Notification, Carousel, Resizable, Root, Questionnaire and Dock already have retained registrations/descriptors; Plot/Chart have current-frame deferred callbacks. Adapters must leave those lifetimes intact or report a separately approved redesign.
- The proposed omission rule must distinguish new immediate callbacks from retained lifecycle/pump work: omitted drawing does not by itself cancel an already-registered notification, provider report or surface exit. Removal/cancellation policy is still per-family work.
- Slider's current controlled bool is submission validity, not changed/requested. Textarea reports last Enter modifiers rather than a universal submit event; OTP already exposes per-frame counts. Proposed richer result fields need additive types and exact adapters, not reinterpretation.

No source contract was altered to fit the proposal. The separately committed [binding audit](COMPONENT_EVENTS_BINDINGS.md) supplies the bridge and language-specific timing/ownership evidence.
