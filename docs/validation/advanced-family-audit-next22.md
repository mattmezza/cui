# Advanced family source audit, next22

Audited against CUI `45c1c92` and frozen GPUI Kit 0.7.1 `87d10ae5e1299d1be18670a37570c5402f952e34` on 2026-10-13. Sources are the pinned checkout `/tmp/cui-gpui-reference`; this audit adds no upstream code or dependency. It is evidence for individual ledger rows, not completion of any entire family. The adjacent JSON contains reviewable feature records and validation outcomes.

## Theme

Existing implementation: public caller-owned `cui_theme` structs; light/dark/high-contrast/terminal palettes; 38 named presets; semantic intent foregrounds, component-specific button/sidebar/chrome/group/chart colors; design sizes, spacing/radius helpers; independent icon loaders; scrollbar skin/motion overrides and two spring settings. `tests/unit/test_components.c` covers preset enumeration, invalid lookup, palette modes, intent tokens and style consumption. New `owner_theme_isolation` renders differently overridden sibling tables in one context, verifies both actual surface colors and confirms no mutation/leak between their theme values. Theme is therefore substantially implemented, not a broad `not_started` item.

Pinned `theme/mod.rs` supplies global registry-backed theme updates, system-appearance synchronization, semantic configuration projection, font and shadow tokens, and synchronization into Base. `theme/registry.rs` supplies JSON loading and directory watching. Local public Theme has no registry/watch/config loader, typography font-family/shadow policy or host automatic appearance observer. Caller assignment and explicit theme passing are the local runtime-switch contract; this audit does not prove system preferences or native appearance notifications.

Pinned `theme/motion.rs` defaults instant/fast/normal/slow to 0/120/180/280ms with enter/exit/move easing and distance tiers. CUI Theme carries two springs and scrollbar policy, not that full motion token vocabulary. Pinned styled Plot projection uses 120ms hover/pointer response and 1000ms quartic-out appearance. CUI Plot accepts explicit duration/easing policies, defaults them to zero, and uses cubic-out when no easing is supplied. This is a concrete styled-default gap, despite substantive clock/reduced-motion implementation. The pinned scrollbar policy also defaults idle/enter/exit/expand to 2s/300ms/500ms/300ms; local shared style documents 1s idle/.15s fade and lacks that full expansion policy.

## Table

Pinned `table/table.rs` composes Header/Body/Footer/Row/Head/Cell/Caption, explicit accessible naming, per-row style refinement, column span/alignment and size-derived cell padding. Local composable Table implements all those structural parts and span/alignment; `tests/unit/test_table.c` covers real geometry, section roles, readonly column headers, custom row colors and caption placement. Its explicit fixed cell widths differ from upstream flex-basis/span minimum sizing, and it has fixed 4px cell padding without a Table size option.

The local root publishes the generic name `Table`; source `Table::accessibility_label` allows a domain-specific name. A caption is separate descriptive content upstream. New headless evidence confirms two visible captions do not silently become root names. Propose append-only `cui_table_begin_ex` with accessible name and sizing/padding options. Static cells currently publish generic `Cell`, and their API does not automatically supply cell text names or row/column indices/spans. Rendering structure exists, but full source semantics need a separate review and explicit metadata API. Static Table uses general surface/background/border tokens; upstream has table/table-even/table-hover/table-row-border tokens and different border styling. Do not label those style contracts complete from structural rendering alone.

## DataTable

Local implementation is substantive: stable-key row/column binding; vertical and horizontal virtualization; controlled/manual selection; row/column/cell modes; caller-bounded multiple selection; keyboard navigation; resizing/reordering; contiguous fixed-left columns; grouped headers; row headers; custom whole-row/cell/header/trailing/empty/loading slots; visible-range/load-more results; context requests; scrollbars; accessible grid counts/indices/selection. Existing `test_table.c` exercises these behaviors, including pointer resize, column drag, fixed-column occlusion, disabled navigation, sorting icons, load-more gating and virtual rendering. Broad not-started rows for these contracts are stale.

Pinned `table/state.rs::perform_sort` cycles Default→Descending→Ascending→Default. Local reduction cycles Default→Ascending→Descending→Default. New test records the local ascending-first result, proves borrowed data is unchanged until the application rebinds reordered rows, then proves selected row identity/semantic row index follows its stable key. It also proves manual selection retains the application-selected row while navigation updates the cursor. This is an exposed source mismatch, not a passing source-parity claim. Propose a source-compatible sort-cycle policy with a compatibility option for existing callers; changing the cycle silently would change behavior.

Pinned delegate sort/reorder/load/visible callbacks correspond locally to synchronous result flags plus explicit host application updates; they are not native async delegate execution. Columns `selectable(false)` upstream suppress selection independently from action controls; local `disabled` marks column/cell semantics inactive, with no dedicated selection-only opt-out flag. Custom child controls retain their own semantics, so disabling column semantics is not an equivalent contract. Upstream optional per-column edge padding is absent locally. Upstream independent vertical/horizontal scrollbar visibility maps locally to a single boolean/shared visibility skin. Dedicated table hover/row-border/striped tokens and source size presets are absent. Dump/export helpers and programmatic scroll-to-row/column functions are absent as public convenience APIs, though callers can manipulate state and inspect the model. No pinned-row feature exists in the pinned source or local API: the documented pinned feature is fixed-left columns, already tested. Do not invent a pinned-row parity requirement.

## Plot

Pinned styled `plot/mod.rs` reexports Base and adds tooltip composition; source files `base/src/plot/{scale,shape,axis,grid,label,path_cache,hover,appear,element}.rs` are the substantive contract. Local `cui_plot.h` and `cui_plot_view.h` contain source-compatible extent Linear, Band/Point/Ordinal scales; stricter navigation Linear/Log10 extensions; line/area/bar/pie/arc/radial/stack/Sankey geometry; axes/grid/labels; raster and mesh paths; source background policies; bounded caches; tooltip cursor/hover lifecycle; independent transition/spring clocks; appearance registries; and PlotElement callbacks. Existing `test_plot.c` and `test_plot_styled.c` extensively cover geometry, pixels, bounds, generation/remount behavior, cache ownership and appearance/reduced-motion. These are not unstarted APIs.

New evidence exercises an X-only pan/zoom viewport while Y remains unchanged and checks an anchored data value, followed by complete interaction opt-out. Pan/zoom is a CUI extension seam, not an implicit guarantee of the pinned Plot trait. A separate owner appearance test proves explicit animation requests redraw while reduced-motion completes another owner's appearance immediately without modifying the first state.

Pinned PlotElement owns current-frame layout/prepaint, hitbox registration and occlusion-aware live pointer tracking. Local API explicitly requires host-supplied current global bounds, pointer and hover. That host seam is implemented but automatic source integration is missing; existing previous-frame `cui_bounds` is insufficient to promise exact current-frame prepaint. The tooltip callback is arbitrary host composition, not a native typed source CrossLine/Tooltip/TooltipItem builder. Local view publishes image/name semantics and primary pointer activation; it documents no keyboard activation or per-datum semantic actions. Native screen-reader data exploration and OS long-press recognition are unverified. Proposed next work: typed tooltip parts and theme-projected default motion can be scoped without Core changes; automatic current-frame measurement/hitbox contracts require a separately reviewed Core design.

## Validation and boundaries

Compile with `-std=c11 -Wall -Wextra -Wpedantic -Werror`; run `build/test_advanced_family_audit` after linking against `build/libcui.a`. Root must register the new test because build configuration is outside this worker's ownership. Strict standard build and the scoped test passed; CTest passed 103/103. Targeted ASan/UBSan with leak detection also passed. Outcomes are recorded in the JSON; no existing sources, headers, gallery, CMake, dist or manifests were edited.

This audit covers headless C behavior and pinned source inspection. It does not validate browser/native renderer parity, screen-reader output, system appearance watchers, platform font selection, mobile or GPU behavior. Existing test evidence should update individual ledger features after integrator review; remaining contracts retain partial/missing status.
